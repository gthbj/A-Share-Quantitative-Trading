#### BigQuery 特别提醒

BigQuery 按**查询扫描的数据量**收费，不是按时间。

```sql
-- ❌ 错误：全表扫描，一次查询可能几十美元
SELECT * FROM stock_prices WHERE code = '600519'

-- ✅ 正确：分区查询，几乎免费
SELECT * FROM stock_prices 
WHERE date BETWEEN '2024-01-01' AND '2024-01-31' 
  AND code = '600519'
```

**必须**：所有表按 `date` + `code` 分区，所有查询带分区条件。否则 exploratory 分析能瞬间烧掉几十美元。

## 二、数据与回测基础

### 2.1 中频策略用什么粒度的数据？

**日线（Daily）是最佳选择。**

- **1min/5min 数据**：信噪比极低，A 股日内随机波动占比高，极易过拟合。数据量爆炸（全市场 1 分钟线一年约 6 亿条），对中频策略无必要。
- **小时线**：一天仅 4 根，信息密度不足，又保留日内噪音，定位尴尬。
- **日线**：经过全天交易去噪，信噪比最优；与几天到几周的持仓周期天然匹配；技术指标与因子库成熟；样本量充足（5000 只 × 250 日 × 10 年 = 1250 万条）。

**例外**：分钟级数据可用于**构建日频聚合特征**（如日内波动率、尾盘成交占比），但核心训练仍应基于日频。

### 2.2 回测价格怎么定？

**默认采用 `next_open`（T+1 开盘价成交）。**

| 参数 | 含义 | 是否推荐实盘 |
|---|---|---|
| `next_open` | 信号日收盘后计算，下一交易日开盘执行 | ✅ 唯一可执行 |
| `current_close` | 信号产生当日收盘价成交 | ❌ 仅用于理论验证 |

**原因**：日线信号基于当日完整数据（收盘、成交量、均线等），物理上只能在 15:00 收盘后才能算出。15:00 之后市场已关闭，不可能以当日收盘价成交。用 `current_close` 回测相当于"预知未来"，会系统性高估收益。

### 2.3 什么是未来函数？

**未来函数（Lookahead Bias）= 在回测中使用了"当时还不知道的信息"来做决策。**

例如：今天 15:00 收盘后，模型根据全天数据算出应买入茅台。若回测用 `current_close`，则假设你在今天 15:00 就已经以收盘价买入——这是不可能的，因为信号在此时还不存在。

**常见陷阱**：
- 当日收盘价成交
- 用未来财务数据（年报发布前使用年报数据）
- 用当日最高/最低价做特征
- 指数成分股调整提前知晓
- 前复权价格用了未来的除权信息
- 在全样本上优化参数后再回测

### 2.4 框架里的 `order_target_percent` 是什么？为什么被禁用？

`order_target_percent(code, pct)` 语义为"将某股票持仓调整至总资产的指定比例"，框架自动计算目标市值、当前价格、应买卖股数。

**禁用原因**：自动计算过程中对"最新价格"的隐式依赖易触发未来函数。框架要求用户显式计算：

```python
price = data[code]["close"]                    # 明确使用的参考价
target_value = portfolio.total_value * 0.1
target_qty = int((target_value / price) // 100) * 100
context.order(code, target_qty - current_qty)  # 明确买卖股数
```

**设计哲学**：显式优于隐式，宁可牺牲便利性，也要保证每笔交易的计算逻辑完全透明。

## 三、机器学习模型

### 3.1 XGBoost / LightGBM 是什么？

它们是**梯度提升决策树（Gradient Boosting Decision Tree, GBDT）**的高效实现，目前量化投资领域最常用的机器学习模型。

#### 核心思想：Boosting

训练很多棵决策树，每棵树专门学习**前一棵树犯过的错误**，最后把所有树的预测结果加起来。

```
第1棵树：预测股价涨跌，误差 = 真实值 - 预测值
第2棵树：专门学习"第1棵树错在哪里"（拟合残差）
第3棵树：学习前两棵树共同的错误
...
最终预测 = 第1棵树 + 第2棵树 + 第3棵树 + ...
```

#### XGBoost vs LightGBM

| 特性 | XGBoost | LightGBM |
|---|---|---|
| 生长策略 | 按层生长（Level-wise）| 按叶子生长（Leaf-wise）|
| 训练速度 | 快 | **更快**（通常 3-10 倍）|
| 内存占用 | 中等 | **更低** |
| 大数据处理 | 优秀 | **更优秀** |
| 推荐使用场景 | 通用，生态最成熟 | **大数据量首选** |

**代码示例**：

```python
import lightgbm as lgb

train_data = lgb.Dataset(X_train, label=y_train)
params = {
    'objective': 'regression',
    'metric': 'rmse',
    'boosting_type': 'gbdt',
    'num_leaves': 31,
    'learning_rate': 0.05,
    'feature_fraction': 0.9,
}

model = lgb.train(params, train_data, num_boost_round=100)
predictions = model.predict(X_test)
```

#### 为什么特别适合金融量化？

| 优势 | 在金融中的体现 |
|---|---|
| 自动学习非线性关系 | PE 和收益的关系不是线性的，树模型自动发现"倒 U 型"模式 |
| 自动特征交互 | 发现"动量高 + 换手率低"的组合效应，无需人工构造交叉因子 |
| 对异常值鲁棒 | 不受涨停、黑天鹅等极端样本的剧烈影响 |
| 可解释性强 | 输出特征重要性，知道"20日动量"比"PE"更重要 |
| 不需要特征标准化 | 只关心数值大小顺序，不关心具体量纲 |

### 3.2 日线中频推荐传统 ML 还是深度学习？

**强烈推荐传统 ML（XGBoost / LightGBM），深度学习在日线中频场景性价比极低。**

| 维度 | XGBoost/LightGBM | 深度学习 |
|---|---|---|
| 数据形态 | 表格因子天然匹配 | 更适合图像、文本、高频序列 |
| 信噪比鲁棒性 | 强。树模型天然抗噪 | 弱。极易把噪音拟合成伪模式 |
| 样本量需求 | 10 万条就能出好效果 | 1250 万条只是起步 |
| 非平稳性适应 | 滚动训练快速适应新环境 | 对新市场 regime 适应能力差 |
| 可解释性 | feature_importance / SHAP | 黑盒 |
| 训练成本 | CPU 几分钟 | GPU 几小时到几天 |

**深度学习什么时候能赢？** 只有在另类数据（NLP、卫星图像）、超高维特征、高频/日内数据、极大资金+算力时才可能优于传统 ML。

**如果你只是用日线 OHLC + 常规技术指标/财务因子，深度学习几乎必然输给 XGBoost。**

#### 推荐的黄金组合

```
特征层：日线因子（100-500个）
    ↓
模型层：LightGBM（滚动训练 + 5-10个模型 ensemble）
    ↓
输出层：预测未来N日收益率排序 → 取 Top-K 等权持仓
```

## 四、绩效指标

### 4.1 Alpha（α）

**超额收益，即剔除市场整体涨跌后，策略凭本事赚到的钱。**

来自 CAPM 模型：

$$R_p - R_f = \alpha + \beta(R_m - R_f) + \varepsilon$$

- **Beta（β）**：承担市场风险的回报（随波逐流的收益）
- **Alpha（α）**：与市场无关的独立收益，反映模型真实的预测能力

**举例**：策略年收益 25%，沪深 300 涨 10%，则 Alpha ≈ 15%。

**警惕**：若策略总收益为正但 Alpha 为负，说明只是在赌大盘方向（靠 Beta 赚钱），策略本身无价值。

### 4.2 夏普比率（Sharpe Ratio）

**风险调整后的收益评分，衡量"每承受一份波动，能赚多少超额收益"。**

$$Sharpe = \frac{R_p - R_f}{\sigma_p}$$

**A 股量化参考标准**：

| 夏普值 | 水平 |
|---|---|
| < 0 | 不如存银行 |
| 0 ~ 1.0 | 及格（沪深 300 长期约 0.3-0.5）|
| 1.0 ~ 1.5 | 优秀量化私募水平 |
| 1.5 ~ 2.0 | 顶级水平 |
| > 2.0 | 需高度警惕未来函数或过拟合 |

**局限性**：夏普惩罚所有波动（上涨也罚）。可结合**索提诺比率（Sortino）**（只罚下跌波动）综合评估。

## 五、策略设计与执行

### 5.1 中频策略是否可以用日内信号当天交易？

**需区分两种模式。**

**模式 A：日线信号 + 日内执行优化（常见且推荐）**
- 晚上基于日线数据确定次日目标持仓
- 次日盘中通过限价单或尾盘执行建仓/减仓
- 目的不是改变交易决策，而是"买得更便宜"、"避开开盘跳空"

**模式 B：日内小时/分钟信号直接驱动交易（谨慎）**
- 盘中小时线金叉即买入，分钟线破位即卖出
- **对中频策略不推荐**：日内信噪比极低；A 股 T+1 导致盘中误判无法当日止损；频繁交易推高手续费

**建议**：中频策略应保持"日线决策、低频调仓"，执行层面的优化边际收益有限。

### 5.2 10 万级别资金的最务实做法

#### 核心原则

1. **策略架构**：日线信号 + T+1 开盘执行。不要搞复杂的日内执行优化。
2. **持仓集中度**：3-8 只，单只仓位 10%-30%。太分散会推高佣金占比，太集中风险过大。
3. **调仓频率**：5-20 日，保持中低频以控制交易成本。
4. **佣金谈判**：尽可能谈到**万 1 免 5**（佣金率 0.01%，免除最低 5 元收费）。这是小资金提升净收益最有效的手段。
5. **摩擦成本意识**：A 股一买一卖综合成本约 0.1%-0.15%。年周转 20 次即成本 2-3%，频繁交易会严重侵蚀本金。

#### 手动交易 vs 自动交易

**完全可以手动交易，而且初期强烈推荐手动。**

- 每周调仓一次，5 只票，每次开盘 2-3 分钟搞定，**月交易时间约 10 分钟**
- 为了省每月 10 分钟的手动操作，去学 QMT/PTrade（通常 50 万资金门槛）、开发自动下单、处理 API 断线和异常，是"用大炮打蚊子"

**手动交易的最大敌人：执行偏差**

| 偏差 | 例子 |
|---|---|
| 时间偏差 | 策略说 9:30 买，你 10:30 才下单 |
| 情绪偏差 | 策略说买，你看着大盘跌不敢买 |
| 遗漏偏差 | 持仓 8 只，只下了 7 只的单 |

**解法**：每晚模型跑完后，生成固定格式的**交易清单**，开盘 5 分钟内按清单执行，不临时改主意。

#### 什么时候才需要自动交易？

| 条件 | 建议 |
|---|---|
| 资金 < 50 万，几天调仓一次 | **手动即可** |
| 资金 50-200 万，日频调仓 | QMT / PTrade 半自动 |
| 资金 > 200 万，多策略并行 | 全自动 + 自建系统 |

#### 佣金谈判

| 佣金方案 | 单笔 1 万买卖成本 | 年周转 20 次总成本（10万本金）|
|---|---|---|
| 默认（万 2.5，最低 5 元）| 15.1 元 | **3,020 元（3%）** |
| **万 1 免 5** | 6 元 | **1,200 元（1.2%）** |
| **差额** | | **省 1,820 元/年** |

**怎么谈**：不要直接在 App 开户（默认佣金高），找券商客户经理明说"我要做量化，资金会逐步加仓，先给我万 1 免 5"。国金、银河、华泰竞争激烈，容易谈。
