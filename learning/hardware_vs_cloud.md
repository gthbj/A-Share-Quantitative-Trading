# 本地硬件 vs 云服务：中频量化策略的基础设施选型

> 本文档对比"自配本地硬件"与"使用云服务"两种方案在日线中频 + LightGBM 场景下的成本、性能与适用性。

---

## 一、方案概述

| 维度 | 本地硬件 | 云服务 |
|---|---|---|
| **前期投入** | 高（一次性购买）| 低（按需付费）|
| **月度成本** | 极低（电费可忽略）| 按使用量计费 |
| **3年TCO** | 通常更低 | 持续支出 |
| **扩展性** | 固定，升级需再买 | 弹性，秒级扩容 |
| **数据安全** | 物理隔离，完全掌控 | 依赖云厂商 |
| **维护成本** | 需自己维护系统 | 云厂商负责基础设施 |
| **可用性** | 关机即不可用 | 24/7 可用 |
| **协作便利性** | 差（物理机器）| 好（共享环境）|

**核心结论**：

> 对于个人/小团队做日线中频量化，**本地硬件是主力，云服务是弹性补充**。两者不是互斥关系，而是互补关系。

## 二、本地硬件方案

### 2.1 Mac 方案

| 配置 | 价格 | 适用场景 |
|---|---|---|
| **Mac mini M5 Pro + 48GB + 1TB** | ¥13,000-16,000 | 性价比首选，固定工位 |
| **MacBook Pro 14" M5 Pro + 48GB + 1TB** | ¥20,000-25,000 | 需要移动办公 |
| **Mac Studio M4 Max + 64GB + 1TB** | ¥25,000-30,000 | 重度研发，大内存需求 |

**优势**：
- 统一内存架构，48GB 内存对日线全市场数据足够
- 功耗极低（Mac mini 待机 <10W，满载 <100W）
- 无噪音（Mac mini/Studio 几乎静音）
- 与云端 GCP BigQuery 通过 Python SDK 无缝协作

**劣势**：
- 内存和 SSD 焊死，无法后期升级
- 无 NVIDIA CUDA，深度学习受限
- 关机后不可用

### 2.2 Windows / Linux PC 方案

| 配置 | 价格 | 说明 |
|---|---|---|
| **i7-13700K + 64GB DDR5 + 1TB NVMe** | ¥8,000-10,000 | 自组台式机，性价比最高 |
| **AMD R7 7700X + 64GB DDR5 + 1TB NVMe** | ¥7,500-9,500 | 多核性能强，LightGBM 训练快 |
| **i9-13900K + 128GB DDR5 + 2TB NVMe** | ¥15,000-18,000 | 顶配，全市场分钟级也能处理 |

**优势**：
- 比同配置 Mac 便宜 30-50%
- 内存和存储可后期升级
- 可加装 NVIDIA 显卡（未来如需深度学习）
- LightGBM 在 x86 上优化更成熟

**劣势**：
- 有噪音（风扇）
- 功耗高（100-300W）
- 需要自己维护系统
- 体积大（台式机）

### 2.3 本地硬件的隐性成本

| 项目 | 年成本 | 说明 |
|---|---|---|
| 电费 | ¥100-300 | Mac 极低，PC 中等 |
| 网络 | ¥1,200-2,400 | 宽带费用 |
| 维护/升级 | ¥0-2,000 | 系统重装、配件更换 |
| **年度隐性成本** | **¥1,300-4,700** | |

## 三、云服务方案

### 3.1 GCP（主力推荐）

#### 计算资源

| 用途 | 实例类型 | 配置 | On-Demand | Spot |
|---|---|---|---|---|
| 日常研发 | n2-standard-8 | 8核32G | ~$0.38/时 | ~$0.08/时 |
| 主力回测 | n2-standard-16 | 16核64G | ~$0.76/时 | ~$0.15/时 |
| 大规模特征工程 | n2-highmem-32 | 32核128G | ~$1.52/时 | ~$0.30/时 |
| 计算密集型 | c2-standard-16 | 16核64G | ~$0.84/时 | ~$0.17/时 |

#### 存储与数据仓库

| 服务 | 价格 | 说明 |
|---|---|---|
| **BigQuery 存储** | $0.02/GB/月 | 历史行情主仓 |
| **BigQuery 查询** | $5/TB（前 1TB/月免费）| 按扫描量计费 |
| **Cloud Storage** | $0.02/GB/月 | Parquet、模型文件 |
| **Cloud Storage 网络出口** | $0.12/GB | 下载到本地 |

#### 月度成本估算

| 使用强度 | 配置 | 月度成本 |
|---|---|---|
| **轻量** | 偶尔开 Spot VM（10小时/月）+ BigQuery | **~$15-30（¥100-220）** |
| **中度** | Spot VM 40小时 + On-Demand 20小时 + BigQuery | **~$55（¥400）** |
| **重度** | Spot VM 100小时 + On-Demand 40小时 + BigQuery | **~$120-150（¥860-1,100）** |

**新用户福利**：$300 免费额度（90天），可覆盖前 3-6 个月轻中度使用。

### 3.2 阿里云（简要对比）

| 维度 | 阿里云 | GCP |
|---|---|---|
| 同配置按量价格 | **低 30-50%** | 较高 |
| Spot 折扣深度 | 3-5 折 | **2-3 折** |
| 数据仓库体验 | MaxCompute（传统）| **BigQuery（Serverless）** |
| 新用户优惠 | 首购 5-7 折 | **$300 免费额度** |
| 中文支持 | **原生** | 英文为主 |

**阿里云更适合**：数据在国内、需要中文技术支持、常驻稳定环境。
**GCP 更适合**：批量回测任务、全球生态、Serverless 体验。

### 3.3 云服务的隐性成本

| 项目 | 成本 | 说明 |
|---|---|---|
| 数据出口费 | $0.08-0.12/GB | 从云端下载结果到本地 |
| 学习成本 | 10-20 小时 | 熟悉 GCP 控制台、权限、计费 |
| 环境配置 | 5-10 小时 | 每次开新实例需配置环境 |
| 潜在超支 | 不可控 | BigQuery 全表扫描可能瞬间几十美元 |

## 五、选择矩阵

| 你的情况 | 推荐方案 | 理由 |
|---|---|---|
| **预算紧张，无本地机器** | GCP Spot + $300 额度 | 前几个月几乎零成本启动 |
| **有现成笔记本/台式机** | 现有机器 + GCP Spot 按需 | 最小投入验证策略 |
| **长期做量化，固定工位** | **Mac mini 48GB + GCP Spot** | 本地主力 + 云端弹性 |
| **需要移动办公** | MacBook Pro 48GB + GCP Spot | 随身研发，云端算力补充 |
| **团队协作（2人以上）** | GCP On-Demand 常驻 + 共享环境 | 环境一致性，协作便利 |
| **要做深度学习** | PC + RTX 4090 / 云端 GPU A100 | GPU 是刚需 |
| **只做回测，不常研发** | 纯 GCP Spot | 不需要本地机器 |

## 六、10万资金的特定建议

对于 10 万本金、日线中频、个人研发者：

### 最优路径

```
阶段 1（0-3个月）：验证期
├── 硬件：现有电脑或 GCP $300 额度
├── 数据：GCP BigQuery（1TB免费查询足够用）
├── 模型：LightGBM CPU 训练
└── 交易：手动交易 + 清单法

阶段 2（3-12个月）：主力研发期
├── 硬件：购入 Mac mini 48GB（¥14,000）
├── 数据：BigQuery 主仓 + 本地 Parquet 缓存
├── 云端：GCP Spot 按需开（月均 $20-50）
└── 交易：手动交易，佣金谈到万1免5

阶段 3（1-3年）：规模化期
├── 硬件：Mac 继续用
├── 云端：GCP Spot 成为批量回测主力
├── 策略：多策略并行，ensemble
└── 交易：资金到50万后考虑 QMT/PTrade
```

### 钱应该花在哪里（按优先级）

| 优先级 | 投入项 | 预估成本 | 收益影响 |
|---|---|---|---|
| 🔴 最高 | 券商佣金（万1免5）| ¥0（谈判）| **年化 +1.8%** |
| 🔴 最高 | 本地内存 32GB+ | ¥0-5,000 | 研发体验核心 |
| 🟡 高 | Mac mini M5 Pro 48GB | ¥14,000 | 5-7年主力机 |
| 🟡 高 | GCP BigQuery 存储 | $2-5/月 | 数据基础设施 |
| 🟢 中 | GCP Spot 弹性算力 | $20-50/月 | 批量回测加速 |
| ⚫ 低 | GPU（任何型号）| — | 对 LightGBM 无用 |
| ⚫ 低 | 阿里云/多云服务 | — | 单一云足够 |

## 七、混合方案的详细工作流

**推荐的最优组合**：本地 Mac 主力研发 + GCP 弹性算力

### 日常工作流

```
本地 Mac（固定使用）
├── 策略代码开发（VS Code / PyCharm）
├── 小数据集验证（<1000只股票，<3年数据）
├── 模型快速迭代（LightGBM CPU 训练）
├── 单策略回测（本地 BacktestEngine）
└── 交易清单生成（每晚）

云端 GCP（按需启动）
├── 全市场历史数据（BigQuery）
├── 大规模特征工程（Spot VM，10-100核并行）
├── 超参搜索（Optuna + Spot VM 集群）
├── 多策略批量回测（Spot VM 跑 overnight）
└── 结果持久化（Cloud Storage）
```

### 数据同步

```
T日收盘
    ↓
国内数据源（Tushare / Wind）
    ↓
阿里云最小 ECS 跳板机（定时同步脚本）
    ↓
GCP Cloud Storage / BigQuery
    ↓
本地 Mac 或 Spot VM 读取分析
```

## 八、常见误区

| 误区 | 真相 |
|---|---|
| "云服务一定比本地贵" | 3年看纯本地更便宜，但云服务提供了弹性和零首付启动 |
| "我需要买很贵的 GPU" | LightGBM 用 CPU 即可，10万资金策略不需要 GPU |
| "一台机器就能搞定所有" | 日线中频策略研发不需要集群，单机足够 |
| "必须选一家云绑定" | 数据格式标准化（Parquet），随时可迁移 |
| "Spot 实例不稳定不能用" | 批量回测任务可断点续跑，Spot 是完美的 |

## 九、总结

| 问题 | 答案 |
|---|---|
| 必须买本地机器吗？ | **不是必须**。先用 GCP $300 额度验证，确认长期坚持再买 |
| 本地买 Mac 还是 PC？ | **Mac mini 48GB** 是甜点（静音、低功耗、够用）；追求性价比买 PC |
| 云服务必须选 GCP 吗？ | 不是必须，但 Spot 折扣 + BigQuery 体验对量化很友好 |
| 最优组合是什么？ | **本地 Mac 主力 + GCP Spot 弹性 + BigQuery 数据仓** |
| 最不该花的钱？ | GPU、多云服务冗余、过度复杂的 MLOps 平台 |

> **基础设施是为策略服务的，不是反过来。在策略没有验证出 Alpha 之前，最小化基础设施投入，把精力集中在因子挖掘和模型迭代上。**
