## 2. 背景与动机

BQML 信号真实撮合回测在 10 万初始资金、最多 3 只持仓的配置下买入了北交所股票。实际个人账户如果没有北交所、科创板、创业板等专项交易权限，即使策略发出买入信号，券商也不会接受买入委托。若回测不显式过滤这些标的，会出现两类问题：

1. 回测收益与真实账户可交易范围不一致。
2. 10 万资金账户会买到需要更高资产门槛或额外风险揭示权限的标的，导致策略评价失真。

本需求要把账户交易权限作为配置项接入数据读取层，默认全部专项权限为 `false`。策略层仍只负责信号和仓位，真实可交易范围由数据源统一过滤。

## 3. 影响模块声明

| 模块 | 是否影响 | 说明 |
|---|---|---|
| `config` | 是 | 新增账户交易权限开关，默认专项权限均为 `false`。 |
| `data_layer` | 是 | `BigQueryDataSource` 根据账户权限过滤股票列表、ADS 候选信号和直接请求的日线股票行情。 |
| `CLI` | 是 | `run_backtest.py` 构造 BigQuery 数据源时注入账户权限配置。 |
| `strategy` | 否 | 不改策略逻辑，策略读取到的 universe 已是过滤后的可交易范围。 |
| `engine` / `account` / `analytics` / `utils` | 否 | 不改撮合、持仓、绩效和工具逻辑。 |
| 回测可复现性 | 是 | 同一配置下结果可复现；权限开关变化会改变可买入标的集合，因此会改变回测结果。 |

## 5. 需求详情

### 5.1 功能目标

新增账户专项交易权限配置，并让 BigQuery 数据源默认过滤当前账户不可交易标的：

| 权限 | 默认值 | 回测影响 |
|---|---:|---|
| 北交所 / BSE | `false` | 过滤 `exchange_code='BSE'`、`market_type='北交所'`、`920/43/83/87/88` 等北交所或股转相关前缀。 |
| 科创板 | `false` | 过滤 `688/689` 等科创板股票。 |
| 创业板 | `false` | 过滤 `300/301` 等创业板股票。 |
| 港股通 | `false` | 当前 A 股策略不直接用港股通，但保留开关用于后续港股通标的过滤。 |
| 新三板 / 全国股转 | `false` | 当前策略不直接用新三板，但保留开关用于后续挂牌公司数据。 |
| 风险警示 ST / *ST | `false` | 过滤名称包含 ST / *ST 的风险警示股票。 |
| 退市整理 | `false` | 过滤名称或市场类型带退市特征的股票。 |
| 融资融券 | `false` | 当前不启用融资融券下单能力，仅作为账户能力声明。 |
| 股票期权 | `false` | 当前不交易期权，仅作为账户能力声明。 |
| 可转债 | `false` | 当前股票策略不交易可转债，仅作为账户能力声明。 |
| 存托凭证 CDR | `false` | 后续如接入 CDR 时默认过滤。 |
| 未知证券信息 | `false` | ADS 信号 join 不到 `dim_security` 时默认不允许买入。 |

### 5.2 交互流程

用户运行回测：

```text
run_backtest.py
  -> 读取 config/backtest.yaml account.trading_permissions
  -> 构造 BigQueryDataSource(trading_permissions=...)
  -> BQML 策略读取 ADS 候选信号
  -> BigQueryDataSource join dwd_dim_security 并过滤不可交易标的
  -> 策略只对过滤后的候选池下单
  -> BacktestEngine / TradeEngine 按原有真实撮合规则执行
```

若用户直接通过 `--universe 920123.SH,688001.SH,000001.SZ` 指定标的，数据源在请求日线股票行情时应过滤掉无权限的北交所和科创板标的，仅返回 `000001.SZ` 的行情。

## 6. 配置变更

新增顶层配置：

```yaml
account:
  trading_permissions:
    allow_bse: false
    allow_star_market: false
    allow_chinext: false
    allow_hk_stock_connect: false
    allow_neeq: false
    allow_risk_warning: false
    allow_delisting: false
    allow_margin_trading: false
    allow_stock_options: false
    allow_convertible_bonds: false
    allow_cdr: false
    allow_unknown_security: false
```

说明：

- `false` 表示当前账户没有该专项权限，策略不得买入对应标的。
- 普通沪深主板股票不新增 `allow_main_board` 开关；普通账户默认可交易主板股票，本需求只建模额外门槛和风险权限。
- 本次只将股票 universe 相关权限接入数据层过滤；融资融券、期权、可转债、港股通、新三板、CDR 开关先作为配置声明，后续接入对应资产或下单能力时复用。

## 7. 不可改动的红线区域

1. 不修改 `BaseDataSource` 抽象接口签名。
2. 不修改 `BacktestEngine`、`TradeEngine`、`Portfolio`、`Position` 的撮合和账户逻辑。
3. 不修改 BQML 策略的买卖规则、固定持有期、仓位分配规则。
4. 不修改 BigQuery DWD / DWS / ADS 表结构和数据。
5. 不删除或覆盖已有回测产物。
6. 不改变 `get_bars()` 返回列语义：仍返回 `code, date, open, high, low, close, volume, amount`。
7. 不改变 `get_stock_list()` 对外返回列：仍返回 `code, name, list_date, industry`。

## 9. 验收标准

### 用例 1：北交所过滤

- 输入配置：`allow_bse: false`
- 输入代码：`920123.SH`
- 修改前行为：如果 ADS 信号包含该代码，策略可能买入。
- 修改后预期行为：`get_bqml_signal_candidates()` 不返回该代码；直接 `get_bars("920123.SH", ...)` 返回空 DataFrame。

### 用例 2：科创板和创业板过滤

- 输入配置：`allow_star_market: false`、`allow_chinext: false`
- 输入代码：`688001.SH`、`300001.SZ`、`000001.SZ`
- 修改后预期行为：前两者过滤，`000001.SZ` 保留。

### 用例 3：权限开启后放行

- 输入配置：`allow_bse: true`、`allow_star_market: true`、`allow_chinext: true`
- 输入代码：`920123.SH`、`688001.SH`、`300001.SZ`
- 修改后预期行为：代码前缀过滤不拦截这些标的；是否最终可买仍由行情数据、ADS 信号、撮合规则决定。

### 回测验证要求

- 策略：`bqml_signal_picker`
- 区间：`2025-03-01` 至 `2025-03-31`
- 初始资金：`100000`
- 预期变化方向：交易记录中不再出现北交所、科创板、创业板、ST 或退市整理股票；若此前亏损由这类标的贡献，最大回撤应相应下降，但收益率不做硬性保证。

## 10. 备注

1. 本需求是账户可交易范围过滤，不是投资建议，也不替代券商适当性判断。
2. 交易权限规则会随监管规则和券商执行口径变化，配置默认值只是当前项目假设。
3. 过滤发生在数据源层，避免每个策略重复实现同一套权限逻辑。
4. 权限过滤会改变候选池，属于预期的回测结果变化，不属于回归。
5. 风险警示和退市整理识别依赖 `dim_security.security_name` / `market_type`。若源数据缺少 ST 标记，需要后续在 DWD 层补强证券状态字段。
