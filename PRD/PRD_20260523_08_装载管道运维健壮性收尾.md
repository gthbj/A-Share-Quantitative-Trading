| 编号 | 文件 / 行号 | 问题 |
|---|---|---|

| E13 | `data_transfer/cleanup_invalid_checkpoints.py`、`data_transfer/restart_cloud_parquet_build.sh` | 硬编码 VM 路径（`/mnt/localssd/...`、`/home/admin/ashare_pipeline`），一次性脚本留在仓库根目录且无 README 说明 |

不解决会带来：

- token 过期导致长时间 GCS/BQ 操作中断

- 跨平台运维步骤无法直接执行
- 仓库中存在用途不清的硬编码脚本，新成员困惑

本 PRD **不动数据**，**不改数据流逻辑**，只修复运维 / 健壮性问题，并收紧未经确认的自加配置。

## 4. 关键文件路径与现有函数签名

```python
# gcs_to_bigquery/pipeline.py
def gcloud_access_token() -> str:
    result = subprocess.run(
        ["gcloud", "auth", "print-access-token", "--quiet"],
        check=True,
        capture_output=True,
        text=True,
    )
    token = result.stdout.strip()
    if not token:
        raise RuntimeError("gcloud did not return an access token")
    return token

def gcloud_credentials():
    from google.oauth2.credentials import Credentials
    return Credentials(gcloud_access_token())

def use_gcloud_access_token(config: dict) -> bool:
    return bool(config.get("auth", {}).get("use_gcloud_access_token", False))

def bq_client(config: dict):
    bigquery = require_bigquery()
    kwargs = {"project": config["project_id"], "location": config.get("location")}
    if use_gcloud_access_token(config):
        kwargs["credentials"] = gcloud_credentials()
    return bigquery.Client(**kwargs)
```

## 5. 需求详情

### 5.1 功能目标

**A. 认证改走 ADC（Google Application Default Credentials）**：

- `bq_client()` / `storage_client()` **默认不传 `credentials` 参数**，让 SDK 自动通过 ADC 链查找凭据（环境变量 / metadata service / gcloud login）。
- `auth.use_gcloud_access_token` 配置保留为可选 fallback，**默认 `false`**。
- 当 `auth.use_gcloud_access_token: true` 时：
  - `gcloud_access_token()` 调用必须带 `timeout=auth.gcloud_token_timeout_seconds`（默认 30s）
  - 包装为 `google.auth.credentials.Credentials` 的子类，**支持 token 自动刷新**（实现 `refresh(request)` 方法重新调用 gcloud subprocess），避免长时间 external table 创建或 audit 查询中断

**B. manifest_path 改为持久路径**：

- 默认值改为 `${HOME}/.local/state/ashare/ods_pipeline_manifest.jsonl`（POSIX）
- Windows 兼容：若 `HOME` 不存在则用 `${USERPROFILE}/AppData/Local/ashare/ods_pipeline_manifest.jsonl`
- 装载启动前确保父目录存在（`mkdir -p` 等效操作）

**C. 跨平台路径修复**：

- `gcs_to_bigquery/pipeline.py` 中所有错误消息里的 `gcs_to_bigquery\requirements.txt` 改为 POSIX 风格 `gcs_to_bigquery/requirements.txt`
- `gcs_to_bigquery/README.md` 所有命令路径改 POSIX 风格

**D. requirements 版本恢复**：

- `google-cloud-storage>=3.10.0`（恢复）
- `google-auth>=2.53.0`（恢复）
- 若实际环境兼容性需要降级，**必须**在 `README.md` 中说明

**E. 删除 / 收紧 codex 自加配置**：

| 配置项 | 旧默认 | 处理 |
|---|---|---|
| `defaults.column_name_character_map` | `V2` | **保留**。当前只使用现有 `standardized_parquet/`，不重生成英文 Parquet；装载 ODS 时仍需兼容可能存在的中文列名 |
| `defaults.allow_unconfigured_tables` | `true` | **改默认 `false`**——未配置的目标表直接拒绝装载（符合 PRD_20260522_02 §5"无法解析的对象状态标 invalid"语义） |
| `defaults.retry_failed` | `true` | **改默认 `false`**——显式重试由 CLI 参数 `--retry-failed` 控制；自动重试可能掩盖问题 |
| `defaults.replace_staging_tables` | `true` | **标 deprecated**——ODS 改为 external table 后不再需要 native load 覆盖策略，由 PRD_10 删除 |
| `defaults.load_strategy: "table_batch"` | 存在 | **标 deprecated**——ODS 改为 external table 后不再需要 table batch load，由 PRD_10 删除 |
| `defaults.max_source_uris_per_job` | `9000` | **保留**——这是 BigQuery 实际限制 |
| `defaults.csv` | 存在 | **保留**——PRD_20260522_02 §7.4 第一版即支持 CSV |

**F. 删除 / 迁移一次性脚本**：

- `data_transfer/cleanup_invalid_checkpoints.py` 和 `data_transfer/restart_cloud_parquet_build.sh` **迁移到 `scripts/legacy/` 目录**
- 在 `scripts/legacy/README.md` 中说明：
  - 这些脚本是 Codex 在 GCE VM `ashare-parquet-worker` 上 ad-hoc 操作时使用的
  - 路径硬编码、仅限当时环境
  - 保留为历史参考，**不再在新流程中调用**

### 5.2 交互流程

```
开发端：
  本机 gcloud auth application-default login → ADC 自动生效
  python gcs_to_bigquery/pipeline.py init  →  无需 gcloud 子进程

CI / GCE VM 端：
  Metadata service 自动提供 service account credentials → ADC 自动生效

Fallback（不推荐，但保留）：
  config.auth.use_gcloud_access_token: true
  →  gcloud subprocess 30s timeout
  →  token 自动刷新（实现 Credentials.refresh）

manifest_path：
  默认: ${HOME}/.local/state/ashare/ods_pipeline_manifest.jsonl
  Windows 默认: ${USERPROFILE}/AppData/Local/ashare/...
  显式覆盖: config.manifest_path 或 CLI --manifest-path
```

## 9. 验收标准

### 9.1 ADC 改造

**用例 1**：本机已 `gcloud auth application-default login`，配置 `auth.use_gcloud_access_token: false`
- 输入：`python gcs_to_bigquery/pipeline.py progress --config gcs_to_bigquery/config.yaml`
- 修改前：依赖 `gcloud auth print-access-token` subprocess
- 修改后：无 subprocess 调用，SDK 通过 ADC 直接连接

**用例 2**：配置 `auth.use_gcloud_access_token: true`，模拟长任务
- 输入：手工 sleep 65 分钟模拟 token 过期后再发 query
- 修改前：query 失败
- 修改后：token 自动刷新，query 成功

**用例 3**：gcloud subprocess 卡死场景
- 输入：用 monkey-patch / mock 让 gcloud subprocess hang 60s
- 修改前：进程永久卡住
- 修改后：30s 后抛 `subprocess.TimeoutExpired`，错误消息明确

### 9.2 manifest_path

- 默认配置下 `manifest_path` 不再指向 `/tmp`。
- POSIX 系统下 `Path(config["manifest_path"]).expanduser()` 解析为 `~/.local/state/ashare/ods_pipeline_manifest.jsonl`。
- 父目录 `~/.local/state/ashare/` 自动创建。

### 9.3 跨平台路径

- `grep -rn 'gcs_to_bigquery\\\\' gcs_to_bigquery/` 无匹配。
- `gcs_to_bigquery/README.md` 所有 `python gcs_to_bigquery/pipeline.py ...` 使用正斜杠。
- 错误消息中 "Install it with: python -m pip install -r ..." 使用 POSIX 路径。

### 9.4 requirements

- `gcs_to_bigquery/requirements.txt` 中：
  - `google-cloud-storage>=3.10.0`
  - `google-auth>=2.53.0`
- 在 `gcs_to_bigquery/README.md` 的 Setup 段无版本降级说明。

### 9.5 配置删减

- `gcs_to_bigquery/config.yaml` 中：
  - `column_name_character_map` 若存在，必须明确为 `V2`，并在注释中说明用于兼容当前 GCS Parquet 贴源字段
  - `allow_unconfigured_tables: false` 或不存在（依赖 default false）
  - `retry_failed: false` 或不存在
  - 出现 `# deprecated, ODS external table no longer uses native load` 注释在 `replace_staging_tables` 和 `load_strategy` 上方
- `python gcs_to_bigquery/pipeline.py create-ods-external --config <未配置表的 config>` 在 GCS 上有未在 `ods_external_tables` 中声明的 target_table 时直接报错"Target table is not configured"，不再默认允许。

### 9.6 脚本迁移

- `data_transfer/cleanup_invalid_checkpoints.py` 和 `restart_cloud_parquet_build.sh` 不在 `data_transfer/` 目录下。
- `scripts/legacy/` 目录存在，包含上述两个文件 + 一个 `README.md`。
- `scripts/legacy/README.md` 包含：
  - 这些脚本仅用于 GCE VM `ashare-parquet-worker` 历史调试
  - 不应在新流程中调用
  - 路径硬编码列表（`/mnt/localssd/...`、`/home/admin/...`）
  - 保留期：可在 PRD_11 完成且回测验证通过后删除

### 9.7 兼容性

- 旧的 `python gcs_to_bigquery/pipeline.py load --config <旧 config>` 命令若保留，只能作为 deprecated 历史兼容入口，并提示改用 `create-ods-external`。
- 本 PRD 完成后，在 ADC 已配置的环境中，**默认配置即可运行**新流程子命令（init-ods / manifest / create-ods-external / progress / sync-manifest / audit-ods）。

## 10. 备注

### 10.1 与其他 PRD 的关系

- **PRD_07（命名迁移）**：可同时进行。改的字段不同（`datasets.*` vs `auth.*` / `defaults.*` / `manifest_path`），合并时 yaml 不会冲突。
- **PRD_09（字段映射）**：PRD_09 不再重生成英文 Parquet，而是把现有 GCS Parquet 的贴源字段映射到 DWD 标准字段。因此本 PRD 必须保留 `column_name_character_map: V2`，避免 ODS 外部表 schema 解析阶段因中文列名兼容性出现不必要风险。
- **PRD_10（ODS 外部表）**：本 PRD 把 `replace_staging_tables` / `load_strategy` 标 deprecated；PRD_10 改为 external table 后删除 native load 相关配置。

### 10.2 风险

- **ADC 在某些环境下未配置**：用户需先 `gcloud auth application-default login` 或在 GCE 上确认 service account 有权限。失败时 SDK 抛 `DefaultCredentialsError`，错误消息已经明确。
- **token 刷新实现**：用 `google.auth.credentials.Credentials` 子类实现 `refresh()` 不算复杂；本 PRD 仅在 `use_gcloud_access_token: true` 时启用，影响面小。
- **配置兼容**：当前 GCS 数据不会重生成，ODS 必须兼容现有 Parquet schema；`column_name_character_map: V2` 是兼容性配置，不作为待删除项。

### 10.3 与 PROJECT_OWNER_PREFERENCES 对齐

- 偏好 #2 "没要求的不做"：本 PRD 只收紧明确有风险的配置，不删除当前装载仍需要的兼容配置。
- 偏好 #3 "只改被要求的部分"：本 PRD 严格不动数据流逻辑。
- 偏好 #4 "给验收标准，别给步骤"：§9 全部按预期行为描述。
