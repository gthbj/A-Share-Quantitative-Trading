## 2. 背景与动机

`analytics/report.py` 生成的 `report.html` 当前只有：
- 7 个核心指标卡片（收益、回撤、夏普等）
- 3 张图（累计收益、回撤、月度热力图）

而 `summary.md` 已包含完整信息：
- I 策略元信息（类、描述、universe）
- II 数据来源（数据源、项目、主表、复权方式）
- III 回测参数（区间、频率、初始资金、基准、bar 总数）
- IV 交易规则（佣金、印花税、滑点、撮合、止损）
- V 核心绩效
- VI 交易统计（笔数）
- VII 费用汇总（总佣金、印花税、过户费、合计、综合费率）
- VIII 完整交易明细
- IX 文件清单

HTML 报告作为最常被打开的可视化产物，缺这些内容用户得切到 summary.md 才能看全，体验割裂。

不修复的后果：报告打开率降低；外部分享时只能发 summary.md（黑底白字易劝退）；HTML 报告作为"最终交付物"地位不足。

## 5. 需求详情

### 5.1 功能目标

扩展 `generate_html_report` 签名，与 `generate_markdown_summary` 对齐，接收：
- metrics（保留原参数）
- strategy_class_path / strategy_doc / universe
- start_date / end_date / initial_capital / frequency / benchmark
- config（交易规则、止损配置）
- buy_count / sell_count / trade_rows / data_source_name

HTML 模板新增章节（按 summary.md 同一顺序）：

```
1. 策略与回测概要（卡片样式）
   - 策略类、描述、universe（chip 列表）、时间区间、频率、初始资金、基准
2. 数据来源
   - 数据源、项目、主表、复权方式
3. 核心绩效（保留原指标卡片，增加：年化收益、最大回撤持续天数）
4. 交易规则
   - 佣金、印花税、过户费、滑点、撮合价格、成交量限制、T+1、止损
5. 收益曲线 / 回撤曲线 / 月度热力图（保留）
6. 交易统计 + 费用汇总（紧凑双列）
7. 交易明细表
   - 默认折叠为 <details>，避免列表过长拖慢页面
8. Footer（保留免责声明）
```

### 5.2 交互流程

- 用户跑回测 → out 目录下生成 `report.html`
- 浏览器打开后看到完整信息（无需切到 markdown）
- 交易明细折叠在 `<details>` 中，点击展开

### 5.3 排版细节

- 维持现有配色与响应式 grid（不引入 CSS 库）
- 交易明细表用 `table { border-collapse: collapse; font-size: 12px; }` 紧凑显示
- universe chip 用 `<span class="chip">510300.SH</span>` 圆角标签样式
- 所有数值字段沿用 metrics.fmt_pct / fmt_float 风格

## 10. 备注

- **风险**：交易明细超大（如分钟级回测一年下来 1000+ 笔）会让 HTML 体积变大，但 `<details>` 折叠后浏览器懒渲染，可接受。极端情况（>10000 笔）可在未来加分页。
- **风险**：HTML 模板字符串替换易出错（`html.replace("{x}", "y")`），应改用 `str.format()` 或 jinja2 风格的 `.format(**kwargs)`。本次仍坚持纯 str 替换以保持依赖最小。
- 不存在 Lookahead Bias。
