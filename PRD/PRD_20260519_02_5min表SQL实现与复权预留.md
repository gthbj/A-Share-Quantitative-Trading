## 2. 背景与动机

PRD_20260519_01 完成了数据源切换至 MaxCompute 的**骨架**，但 `MaxComputeDataSource` 的全部三个抽象方法在被调用时仍抛 `NotImplementedError`，框架处于"连得上但取不到数据"的状态。

本次通过 pyodps 直接调研 `a_share_historical_data` 项目，获得了以下关键事实，需要据此填充 SQL 实现：

### 2.1 调研结果摘要

| 项 | 实际值 |
|---|---|
| 项目里的表 | `cn_stock_kline_5min`、`stock_60min_data`、`stock_minute_data`（**后两张由项目所有者声明后续会废弃**，本次不接入） |
| 表大小 | `cn_stock_kline_5min` 约 228 MB |
| 分区字段 | `year_month` STRING，格式 `YYYYMM`（如 `200006`） |
| 分区覆盖 | 31 个分区，范围 `200006` ~ `200212`（**仅 2000-06 ~ 2002-12，2.5 年**） |
| 列结构 | `trade_time DATETIME`、`code STRING`、`name STRING`、`open/close/high/low DOUBLE`、`volume BIGINT`、`amount DOUBLE`、`change_pct/amplitude DOUBLE`、`year_month STRING` |
| 代码格式 | 表中为 **`shXXXXXX` / `szXXXXXX`**（小写前缀 + 裸代码，如 `sh600000`、`sz000001`） |
| 复权状态 | 表无 `adjust` 字段，数据为**不复权原始价** |
| 样本行 | `{trade_time: 2000-06-09 09:35, code: 'sh600000', name: '浦发银行', open: 24.0, close: 24.24, high: 24.24, low: 24.0, volume: 834, amount: 2011907.0}` |

### 2.2 项目所有者的决策（已确认）

- **数据时间范围不匹配**：当前默认回测区间（2020-2023）不在数据范围内。所有者选择 **c 方案**：本次仅做代码骨架，**不动 config 默认日期**，数据填充由另外的需求负责。
- **复权处理**：所有者后续会传入一张**复权因子表**，本次**先做接口预留**：保持 `adjust` 参数签名不变，传入 `qfq/hfq` 时打 warning 日志，预留 `_apply_adjust()` 方法。
- **其他周期**（daily / 1min / 15min / 30min / 60min）：所有者选 A 方案（再建专用表），本次**暂不实现**，对应路径抛 `NotImplementedError` 提示"表尚未建立"。

### 2.3 不实现的后果

- `MaxComputeDataSource` 继续处于不可用状态，整个回测框架无法跑通，前一份 PRD 的成果空转。
- 数据填充与复权表等后续需求无法继续推进（缺少可工作的基线）。

### 2.4 对回测行为的影响

- 5min 周期回测变得可运行（前提是回测区间落在 2000-06 ~ 2002-12 之内）。
- 由于本次返回的是原始价，**基于复权后价格的策略在复权表接入前结果可能与 AKShare 模式有差异**——这是已知风险，由后续复权表 PRD 解决。
- 回测可复现性：相同输入 → 相同输出（MaxCompute 表为历史归档，无未来函数风险）。

## 5. 需求详情

### 5.1 功能目标

1. **5min K 线查询**：实现 `_fetch_minute_bars(period="5min")` 的完整 SQL 路径。
2. **代码格式双向映射**：上层始终用框架格式 `XXXXXX.SH/SZ`；数据源内部映射为表格式 `shXXXXXX/szXXXXXX`；返回 DataFrame 时再映射回框架格式。
3. **分区裁剪**：根据请求的 `[start_date, end_date]` 计算 `year_month` 列表，SQL 中用 `year_month IN (...)` 触发分区裁剪，避免全表扫描。
4. **复权接口预留**：
   - `adjust` 参数继续接收，签名不变。
   - 当 `adjust ∈ {"qfq", "hfq"}` 时，打 **warning** 日志："当前 MaxCompute 数据源未接入复权表，返回原始价"。
   - 当 `adjust = "none"` / `None` / 其他 → 不打 warning。
   - 预留 `_apply_adjust(df, code, adjust) -> pd.DataFrame` 方法，本次实现为 `return df`（占位）。
5. **股票列表派生**：`get_stock_list()` 用 `SELECT DISTINCT code, name FROM cn_stock_kline_5min`，返回包含 `code`、`name`、`list_date`(空)、`industry`(空) 列的 DataFrame。`code` 列映射回框架格式。
6. **指数成分股**：`get_index_constituents()` 返回**空列表** + 一条 warning 日志（不抛错），不阻塞策略运行。
7. **其他周期显式拒绝**：`period ∈ {"daily", "1min", "15min", "30min", "60min"}` 时抛 `NotImplementedError`，错误信息明确指出对应表（`tables.daily` / `tables.kline_1min` 等）尚未建立。
8. **错误清晰化**：所有 `NotImplementedError` 的消息必须列出待补字段或待建表名，便于使用者快速定位。

### 5.2 代码格式映射规则

**框架格式 → 表格式**（用于 SQL `WHERE code = ?`）：

| 框架输入 | 映射结果 |
|---|---|
| `600000.SH` | `sh600000` |
| `000001.SZ` | `sz000001` |
| `XXXXXX`（裸代码，无后缀） | 按前缀推断：`60`/`68`/`51`/`56`/`58`/`11` → `shXXXXXX`；`00`/`30`/`15`/`16` → `szXXXXXX`；其他 → 默认 `sh` + 打 warning |

**表格式 → 框架格式**（用于返回 DataFrame 的 `code` 列）：

| 表中值 | 映射结果 |
|---|---|
| `sh600000` | `600000.SH` |
| `sz000001` | `000001.SZ` |
| 其他前缀 | 原样保留 + 打 warning |

实现为模块内私有方法：`_to_exchange_code(framework_code: str) -> str` 与 `_to_framework_code(exchange_code: str) -> str`。

### 5.3 分区列表计算

```python
def _year_months_in_range(start_date: str, end_date: str) -> List[str]:
    """根据 [YYYYMMDD, YYYYMMDD] 返回覆盖的 year_month 列表（YYYYMM）。

    示例：("20000609", "20020815") -> ["200006", "200007", ..., "200208"]
    """
```

SQL 拼接示意（参数化以防注入）：

```sql
SELECT
    code,
    TO_CHAR(trade_time, 'yyyymmddhh24mi') AS date,
    open, high, low, close,
    volume, amount
FROM a_share_historical_data.cn_stock_kline_5min
WHERE code = '<exchange_code>'
  AND year_month IN ('<ym1>', '<ym2>', ...)
  AND TO_CHAR(trade_time, 'yyyymmdd') >= '<start_date>'
  AND TO_CHAR(trade_time, 'yyyymmdd') <= '<end_date>'
ORDER BY trade_time;
```

> 备注：`TO_CHAR(trade_time, 'yyyymmddhh24mi')` 是 MaxCompute 的标准日期格式化函数，结果为 12 位字符串，与框架的分钟级 `date` 列格式一致。如调研时发现 MaxCompute 当前版本对该格式串支持有差异，可改为 `DATE_FORMAT(trade_time, '%Y%m%d%H%i')`——以联调结果为准，**不属于 PRD 强制约束**。

### 5.4 交互流程

```text
get_bars("600000.SH", "20000601", "20020815", period="5min", adjust="qfq")
│
├─ 0. period 路由：
│     period == "5min" → _fetch_minute_bars()
│     period in {"daily","1min","15min","30min","60min"} → NotImplementedError
│     其他 → ValueError
├─ 1. 缓存检查（沿用 LocalStorage，键为 norm_code + period）
│     完全命中 → 直接返回
├─ 2. _fetch_minute_bars():
│     ├─ 2a. _to_exchange_code("600000.SH") → "sh600000"
│     ├─ 2b. _year_months_in_range("20000601","20020815") → ["200006",...,"200208"]
│     ├─ 2c. 拼 SQL（参数化），调用 _execute_sql()
│     └─ 2d. 列标准化：
│            - date：DATETIME → 12 位 YYYYMMDDHHMM 字符串
│            - code：sh600000 → 600000.SH（_to_framework_code）
│            - 保留 [code, date, open, high, low, close, volume, amount]
├─ 3. _apply_adjust(df, code, adjust)
│     当前：return df；adjust ∈ {qfq,hfq} → logger.warning("未接入复权表，返回原始价")
├─ 4. 与本地缓存合并、去重，写回
└─ 5. 按 [start_date, end_date] 过滤后返回
```

`get_stock_list()` 流程：

```text
get_stock_list()
│
├─ 1. 缓存检查（LocalStorage.load_stock_list）
├─ 2. SQL: SELECT DISTINCT code, name FROM cn_stock_kline_5min
├─ 3. 列扩充：list_date = ""、industry = ""
├─ 4. code 列：_to_framework_code 映射回框架格式
├─ 5. 写缓存
└─ 6. 返回 DataFrame[code, name, list_date, industry]
```

`get_index_constituents(index_code)` 流程：

```text
logger.warning(f"MaxCompute 数据源暂未接入指数成分股表，返回空列表（请求 index_code={index_code}）")
return []
```
