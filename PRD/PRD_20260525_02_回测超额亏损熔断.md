## 2. 问题描述

当前 Cloud Run 月度走步 ML 回测会从 2020-01-02 一直跑到 2026-04-30。若策略在早期已经相对沪深300出现不可接受的超额亏损，继续跑完整区间会浪费 GCP 计算时间，也会延后亏损构成分析。

期望行为：回测逐日生成诊断记录后，若 `excess_vs_hs300_pct <= -0.10`，立即停止后续交易日循环，并保留已生成的 NAV、逐日诊断 CSV、持仓/候选股日志与报告，用于分析亏损由哪些交易日、持仓和买卖行为构成。

最小复现路径：

1. 在项目根目录运行 ML 多周期策略回测，并启用逐日诊断。
2. 参数加入 `--early-stop-excess-vs-hs300 -0.10`。
3. 观察任意交易日 `DAY_SUMMARY excess_vs_hs300_pct` 小于等于 `-0.10`。
4. 修改前行为：回测继续跑到 `--end`。
5. 修改后行为：当日记录写入后输出 `EARLY_STOP` 日志，回测结果截止到触发日。

## 5. 需求详情

### 功能目标

1. `BacktestEngine` 支持可选参数 `early_stop_excess_vs_hs300`。
2. 参数为空时，行为与当前完全一致。
3. 启用逐日诊断且已加载沪深300对比基准时，每日收盘记录生成后判断 `summary["excess_vs_hs300_pct"]`。
4. 若该值小于等于阈值，记录 `early_stop_triggered=True`、触发日期、触发值、阈值与原因，并停止后续交易日。
5. CLI 增加 `--early-stop-excess-vs-hs300`，本次 Cloud Run 回测传入 `-0.10`。
6. 熔断后仍按现有流程输出 NAV、图表、summary、daily diagnostics，并归档到 GCS。

### 交互流程

用户启动回测并传入阈值 → 引擎逐日交易与撮合 → 收盘后生成 `DAY_SUMMARY` → 判断相对沪深300超额收益 → 达到亏损阈值时输出 `EARLY_STOP` → 退出回测循环 → 输出已有结果 → 用户分析截止日前的亏损构成。

## 9. 验收标准

用例 1：阈值触发

- 输入：`excess_vs_hs300_pct=-0.105`，CLI 参数 `--early-stop-excess-vs-hs300 -0.10`
- 修改前行为：继续运行下一交易日
- 修改后预期：当前日记录保留，`early_stop_triggered=True`，输出 `EARLY_STOP`，结果截止触发日

用例 2：未达到阈值

- 输入：`excess_vs_hs300_pct=-0.08`，阈值 `-0.10`
- 修改前行为：继续运行
- 修改后预期：继续运行，且不输出 `EARLY_STOP`

用例 3：未启用逐日诊断或基准缺失

- 输入：`early_stop_excess_vs_hs300=-0.10`，但 `summary["excess_vs_hs300_pct"]=""`
- 修改后预期：不熔断，并输出可诊断 warning 或保持静默继续

回测验证要求：

- 策略：`ml_multi_horizon_picker`
- 区间：`20200102` 到 `20260430`
- 初始资金：`100000`
- 参数：`--daily-diagnostics --early-stop-excess-vs-hs300 -0.10`
- 预期：若策略相对沪深300超额亏损触达 -10%，回测在触发日停止，并保留可用于亏损构成分析的 `daily_log`、`daily_positions`、`daily_candidates`。

## 10. 备注

熔断阈值是回测控制参数，不是实盘交易规则。它用于快速发现策略失效区间和亏损来源，不应被解释为策略卖出信号或风险预算逻辑。若后续要做实盘级风险熔断，应另起 PRD，并明确账户级平仓、暂停买入和恢复条件。
