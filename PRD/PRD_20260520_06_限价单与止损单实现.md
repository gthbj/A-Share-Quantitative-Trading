## 2. 背景与动机

`engine/trade_engine.py` 的 `OrderType` 已定义三种枚举：

```python
class OrderType(Enum):
    MARKET = "market"
    LIMIT = "limit"
    STOP = "stop"
```

但 `_try_fill()` 内部**只处理 MARKET**：

```python
if self.price_type == "next_open":
    price = bar.get("open", 0.0)
else:
    price = bar.get("close", 0.0)
```

无视 `order.order_type / order.price / order.stop_price`，所有订单都按 next_open 或 current_close 价撮合。

后果：
- 用户传入 LIMIT 订单（带 price=10.5），引擎仍按 open 价成交，完全无视限价
- 用户传入 STOP 单（带 stop_price=9.5），同样不会触发
- `OrderType` 这个 enum 形同摆设，造成误导

不修复的后果：
- 任何带价格条件的策略（如止盈、分段止损、网格交易）无法回测
- 用户看 OrderType 三选项以为支持，实际上只 MARKET 工作

## 5. 需求详情

### 5.1 功能目标

**A. `Context` 新增 limit_order / stop_order 接口**

```python
def limit_order(self, code: str, amount: int, price: float) -> None:
    """挂限价单。amount 正负号同 order()。"""
    side = OrderSide.BUY if amount > 0 else OrderSide.SELL
    qty = abs(amount)
    if qty == 0:
        return
    if price <= 0:
        raise ValueError(f"限价必须为正数，传入 {price}")
    self._orders.append(Order(
        code=code, side=side, qty=qty, 
        order_type=OrderType.LIMIT, price=price
    ))

def stop_order(self, code: str, amount: int, stop_price: float) -> None:
    """挂止损单。amount 正负号同 order()。"""
    side = OrderSide.BUY if amount > 0 else OrderSide.SELL
    qty = abs(amount)
    if qty == 0:
        return
    if stop_price <= 0:
        raise ValueError(f"止损价必须为正数，传入 {stop_price}")
    self._orders.append(Order(
        code=code, side=side, qty=qty,
        order_type=OrderType.STOP, stop_price=stop_price
    ))
```

**B. `TradeEngine._try_fill` 按 order_type 路由撮合规则**

撮合规则（基于当前 bar 的 [open, high, low, close]）：

| OrderType | 买入触发条件 | 卖出触发条件 | 成交价 |
|---|---|---|---|
| MARKET | 总能撮合 | 总能撮合 | open (next_open) 或 close (current_close)，叠加滑点 |
| LIMIT | bar 的 low ≤ price | bar 的 high ≥ price | order.price（不再叠加滑点，限价单自带价格约束） |
| STOP（卖出） | — | bar 的 low ≤ stop_price | open 或 stop_price（取更不利的，保守估计） |
| STOP（买入） | bar 的 high ≥ stop_price | — | open 或 stop_price（取更不利的） |

**注意**：STOP 单的成交价采用"更不利"逻辑，避免假定瞬间触发完美成交带来的乐观偏差。

涨跌停判定逻辑保持：
- 限价单也要满足 prev_close ± 10% 范围

成交量限制保持：
- 单笔 ≤ volume_limit * bar.volume，超出截断

**C. 在 ARCHITECTURE.md §2.3 / §4 添加限价/止损撮合规则说明**

### 5.2 交互流程

策略代码示例：

```python
# 策略示例：金叉买入 + 5% 止盈限价单
def handle_data(self, context, data):
    bar = data["510300.SH"]
    if 金叉信号:
        # 市价买入
        context.order("510300.SH", 1000)
        # 在 5% 涨幅处挂限价卖出（止盈）
        context.limit_order("510300.SH", -1000, bar["close"] * 1.05)
```

引擎在后续每根 bar 检查所有挂单：
- 限价卖出单：只要某根 bar 的 high ≥ 1.05 倍买入价，即可成交
- 否则订单一直挂着，**直到策略主动取消**（本期不实现取消接口，挂单不过期）

## 9. 验收标准

### 9.1 用例 1：限价买入触发

输入：
```python
order = Order(code="510300.SH", side=OrderSide.BUY, qty=100, 
              order_type=OrderType.LIMIT, price=10.0)
bar = pd.Series({"open": 10.5, "high": 11.0, "low": 9.5, "close": 10.8, 
                 "volume": 1000000, "prev_close": 10.5})
```

修改前：
- 按 next_open 成交价 10.5，无视 price=10.0

修改后：
- bar.low=9.5 ≤ 10.0，触发限价单
- 成交价 = 10.0
- Fill.price == 10.0

### 9.2 用例 2：限价买入不触发

输入：
```python
order = Order(code="510300.SH", side=OrderSide.BUY, qty=100,
              order_type=OrderType.LIMIT, price=9.0)
bar = pd.Series({"open": 10.5, "high": 11.0, "low": 9.5, "close": 10.8, ...})
```

- bar.low=9.5 > 9.0，限价未触及
- 返回 None（无 Fill）

### 9.3 用例 3：止损卖出触发，按更不利价

输入：
```python
order = Order(code="510300.SH", side=OrderSide.SELL, qty=100,
              order_type=OrderType.STOP, stop_price=9.5)
bar = pd.Series({"open": 9.8, "high": 10.0, "low": 9.0, "close": 9.2, 
                 "volume": 1000000, "prev_close": 10.0})
# 持仓充足
```

修改后：
- bar.low=9.0 ≤ 9.5，触发止损
- 成交价 = min(open, stop_price) = min(9.8, 9.5) = 9.5（卖出取更低 = 更不利）
- Fill.price == 9.5

### 9.4 用例 4：MARKET 单回归

输入：
```python
order = Order(code="510300.SH", side=OrderSide.BUY, qty=100,
              order_type=OrderType.MARKET)
```

- 行为完全保持现状（open 价 + 滑点）

## 10. 备注

- **风险 1**：限价单是否被 next_open / current_close 配置影响？答：**不影响**。限价单按 order.price 成交（满足触发条件时），price_type 配置仅影响 MARKET 单。
- **风险 2**：止损单的"更不利"逻辑选择。买入止损：触发后买入价取 max(open, stop_price)；卖出止损：取 min(open, stop_price)。这与真实市场略有不同（真实可能更不利于 stop_price），但在 backtesting 中保守估计是优选。
- **风险 3**：未实现订单 TTL（过期）与取消接口。挂单永远有效直到成交或回测结束，可能与真实长效订单不符。下个 PRD 可扩展 Order.expire_date。
- 不存在 Lookahead Bias：限价/止损判定均基于当前 bar 的 high/low（属于该 bar 已知数据）。
