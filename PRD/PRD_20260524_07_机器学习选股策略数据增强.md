## 2. 背景与动机

当前 `strategy/ml_stock_picker` 仍是早期实现：训练和回测都只使用 Python 从日 K 线临时计算的 17 个技术特征，`train_config.yaml` 仍指向旧 dataset `ashare_core`，且没有模型文件时会随机选股。现在 BigQuery 已经生成并验收以下可用数据：

- `ashare.dws_equity_daily_features`
- `ashare.dws_equity_valuation_features`
- `ashare.dws_equity_fundamental_features`
- `ashare.dws_equity_event_money_flow_features_1d`
- `ashare.ads_signal_ml_stock_picker_1d`
- `ashare.ads_signal_event_money_flow_1d`

如果 ML 策略继续只用本地滚动技术指标，会浪费现有 DWS 数据，并且训练/回测口径与 BigQuery 特征层不一致。更严重的是随机 fallback 会导致没有模型文件时回测不可复现。

本需求目标：让 ML 选股策略优先使用现有 BigQuery DWS 增强特征；训练脚本支持直接读取 DWS 生成训练集；策略没有模型时使用可解释、可复现的增强打分 fallback。

是否影响回测结果可复现性：是。没有模型文件时，从随机选股改为确定性 score fallback，同一输入数据和参数应得到相同选股结果。

## 5. 需求详情

### 5.1 功能目标

1. 增强 ML 特征集：
   - 保留原 17 个技术特征。
   - 新增估值/基本面特征：`pe_basic`、`pb`、`roe`、`gross_margin`、`net_margin`、`debt_to_assets`、`market_cap` 等。
   - 新增事件/资金流特征：`net_inflow_to_amount`、`main_net_inflow_to_amount`、`dragon_tiger_net_to_amount`、`limit_up_streak`、`is_kpl_event`。

2. 训练脚本支持 DWS 数据源：
   - `data_source: bigquery_dws`
   - 从 `ashare.dws_equity_daily_features` 左连接 fundamental 与 event/money flow DWS。
   - 在 SQL 中生成未来 `label_horizon` 日收益标签，仅用于训练。
   - 按日期截面 top/bottom 分位数生成分类标签。

3. 回测策略支持 DWS 快照：
   - 默认 `feature_source: auto`，当数据源是 BigQuery 且 DWS 表可用时读取 DWS 快照。
   - 若 DWS 查询失败或非 BigQuery 数据源，则回退到本地技术特征计算。
   - 模型预测时按 `feature_set` 使用 `technical` 或 `enhanced` 列。

4. 没有模型时不再随机：
   - 使用增强 fallback score。
   - score 只使用当前日及历史已知字段，不使用未来收益。
   - 输出保持确定性，便于回测复现。

### 5.2 交互流程

```text
python strategy/ml_stock_picker/train.py --config strategy/ml_stock_picker/train_config.yaml
  -> data_source=bigquery_dws
  -> 查询 ashare.dws_* 增强特征
  -> 构建截面标签
  -> 按时间切分 train/validation
  -> 保存模型和 validation metrics
```

```text
python run_backtest.py --preset ml_stock_picker
  -> 初始化 MLStockPickerStrategy
  -> 调仓日优先查询 BigQuery DWS 当前日期特征快照
  -> 模型预测；若模型缺失则使用 deterministic fallback score
  -> Top-K 等权下单，仍遵循 next_open 成交
```

## 6. 配置变更

| 配置项 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `params.feature_source` | string | `auto` | `auto` / `dws` / `local`，控制回测特征来源 |
| `params.feature_set` | string | `enhanced` | `technical` / `enhanced`，控制模型输入列 |
| `params.use_deterministic_fallback` | bool | `true` | 模型缺失或预测失败时使用确定性 score |
| `data_source` | string | `bigquery_dws` | 训练脚本默认读取 DWS 增强特征 |
| `bigquery.dataset` | string | `ashare` | 当前正式 BigQuery dataset |
| `train.validation_ratio` | float | `0.2` | 训练集尾部时间切片作为验证集 |

## 7. 不可改动的红线区域

- 不修改 `BaseDataSource` 抽象接口签名。
- 不修改回测引擎撮合时序，继续使用信号日收盘后生成、下一交易日开盘成交。
- 不把未来收益或 label 字段用于回测 live signal。
- 不删除或重建任何 BigQuery / GCS 生产数据。
- 不引入必须联网下载的新依赖。
- 不改变已有 `technical` 17 维特征名，保证旧模型仍可按 `feature_set=technical` 使用。
- 不修改 `engine/*`、`account/*`、`analytics/*`。

## 9. 验收标准

1. 配置验收：
   - `strategy/ml_stock_picker/train_config.yaml` 不再指向 `ashare_core`。
   - `config.yaml` 增加 `feature_source`、`feature_set`、`use_deterministic_fallback`。

2. 测试用例输入输出：
   - 输入：包含原 17 个技术字段、`pe_basic=20`、`pb=2`、`roe=0.12`、`net_inflow_to_amount=0.03` 的一行特征。
   - 预期输出：`FeatureEngineer.feature_columns("enhanced")` 覆盖这些字段，fallback score 为确定性数值。
   - 输入：模型缺失且两只股票 feature row 固定。
   - 预期输出：每次排序结果一致，不调用随机数。

3. 回测验证要求：
   - 参数：`python run_backtest.py --preset ml_stock_picker --start 20200101 --end 20201231`
   - 预期方向：若模型文件不存在，策略仍可运行并产生可复现交易；不会再出现随机 fallback 日志。

4. 单元测试：
   - 新增 ML 策略测试通过。
   - 现有 BigQuery pipeline 测试不因本需求失败。

5. 数据类型验收：
   - BigQuery 日 K 线和本地缓存命中路径返回的 `open/high/low/close/volume/amount` 可参与 float 运算，不因 Decimal 与 float 混用导致撮合失败。

## 10. 备注

- 当前增强 fallback score 不是训练模型的替代品，只是为了避免模型缺失时随机回测。正式策略收益仍应以训练模型和 out-of-sample 验证结果为准。
- DWS 快照查询只在调仓日执行，且按 `date + equity_code` 过滤，避免在回测循环中扫描全表。
- `feature_set=technical` 保持兼容旧模型；新模型建议使用 `feature_set=enhanced` 重新训练。
