## 2. 背景与动机

用户已确认：

- 不重生成 GCS Parquet。
- 不创建 `standardized_parquet_v2/`。
- ODS 不再把 GCS Parquet 复制成 BigQuery native 表。
- 当前 GCS prefix 是唯一正式输入源：

```text
gs://data-aquarium/a-share/standardized_parquet/
```

本 PRD 的目标是基于该 prefix 创建 `ashare.ods_*` BigQuery external table，让 ODS 成为 GCS 的贴源查询层，避免重复存储。

由于 PRD_12 已明确要求生成完整 DWD 层，本 PRD 的最终验收不再只覆盖 5 张 P0 表。5 张 P0 表只作为 smoke/audit 的重点样例；最终 ODS external table 必须覆盖当前 GCS manifest 中全部源表（当前预期 36 张），为完整 DWD 转换提供输入。

## 5. 需求详情

### 5.1 功能目标

- 复用当前 GCS Parquet。
- 不启动 `ashare-parquet-worker`。
- 不写入任何 v2 GCS prefix。
- 不创建 native ODS 业务数据表。
- 创建或确认 `ashare` dataset。
- 创建或更新 `ashare.ods_*` external table，最终覆盖 manifest/config 中全部源表（当前预期 36 张）。
- 5 张 P0 ODS 表必须优先可查，但不能把 P0 通过等同于 PRD_11 完成。
- 同步 `ashare.ods_external_manifest`。
- 写入 `ashare.ods_external_errors`。
- `audit-ods` 全覆盖通过后，允许 PRD_12 启动完整 DWD 转换。

### 5.2 交互流程

```text
现有 GCS Parquet standardized_parquet/
  -> manifest 扫描对象
  -> create-ods-external 创建 ashare.ods_* external table
  -> sync-manifest 写 ashare.ods_external_manifest
  -> audit-ods 验证 external table 可查、schema 可读、GCS 对象可对账
```

失败时：

```text
external table 创建失败
  -> 不产生业务数据副本
  -> 错误写入 ods_external_errors
  -> 修复配置或权限后重跑 create-ods-external
```

## 9. 验收标准

### 9.1 GCS 输入源

- `gs://data-aquarium/a-share/standardized_parquet/` 可列出对象。
- 对象数约 `13744`。
- 不存在本 PRD 新建的 `standardized_parquet_v2/`。

### 9.2 ODS external table

完整 ODS external table 必须满足：

- `ashare.ods_*` 表数量与 manifest/config 中的目标源表数量一致，当前预期为 36 张。
- 每张非空源表都必须有对应 `ods_*` external table。
- 不允许静默跳过源表；无法创建的表必须写入 `ashare.ods_external_errors` 并导致 audit 失败。

P0 smoke 表必须全部存在：

- `ashare.ods_fact_equity_kline_1d`
- `ashare.ods_fact_fund_kline_1d`
- `ashare.ods_fact_index_kline_1d`
- `ashare.ods_fact_board_component_1d`
- `ashare.ods_dim_security`

每张表的 `bq show --format=prettyjson` 必须显示：

- 存在 `externalDataConfiguration`
- `sourceFormat == "PARQUET"`
- `sourceUris` 指向 `gs://data-aquarium/a-share/standardized_parquet/`

### 9.3 manifest 完整性

`ashare.ods_external_manifest` 中：

- 本次 batch 的 GCS 对象记录数与扫描对象数一致。
- manifest 中 `source_table` 去重数量与 `ods_external_tables` 覆盖数量一致，当前预期为 36。
- `gcs_uri` 全部以 `gs://data-aquarium/a-share/standardized_parquet/` 开头。
- 不出现 `standardized_parquet_v2`。
- 每条记录可关联到一个 `ods_*` external table。

### 9.4 audit-ods

`audit-ods` 输出至少覆盖：

- external table 存在。
- external table 可执行 sample query。
- schema 可读取。
- GCS source URI 与配置一致。
- GCS 对象数与 manifest 对账通过。
- ODS 表覆盖数与 manifest 源表数一致。
- 错误表中无阻塞类错误。

### 9.5 成本估算

工作总结文档必须记录：

- 本 PRD 未产生 BigQuery native ODS 业务数据存储。
- external table audit 查询扫描量。
- GCS 读取对象规模。
- 本 PRD 没有新增 VM compute 费用。
