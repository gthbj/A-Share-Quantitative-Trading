## 2. 背景与动机

当前框架内的所有策略（双均线、动量、多因子）均缺乏统一的止损纪律。当市场出现持续下跌时，策略会持有浮亏仓位直至下一个反向信号出现，导致回撤放大、资金占用时间延长。在真实 A 股交易中，机构投资者普遍会设置止损线（如浮亏 5% 或 8% 强制离场），本框架作为高保真模拟系统，应当支持这一核心风控机制。

**不实现的后果**：
- 策略回测结果过于乐观，无法反映真实交易中的风控损耗。
- 后续新增策略需要各自重复实现止损逻辑，造成代码冗余且标准不一。

### 4.2 `account/position.py` — 持仓盈亏计算

```python
# account/position.py
@dataclass
class Position:
    code: str
    total_qty: int = 0
    sellable_qty: int = 0
    cost_price: float = 0.0
    _buy_records: Dict[str, int] = field(default_factory=dict, repr=False)

    def market_value(self, current_price: float = 0.0) -> float:
        return self.total_qty * current_price

    def profit_ratio(self, current_price: float = 0.0) -> float:
        if self.cost_price == 0:
            return 0.0
        return (current_price - self.cost_price) / self.cost_price
```

## 5. 需求详情

### 5.1 功能目标

1. **全局止损开关**：在 `config/backtest.yaml` 中增加止损配置，支持启用/禁用止损机制，以及设置止损阈值（浮亏比例）。
2. **自动触发**：`BacktestEngine` 每日收盘后自动检查所有持仓的浮亏比例，**无需策略层感知或修改任何策略代码**。
3. **T+1 兼容**：当日买入的股票（不可卖部分）不参与止损检查；仅对 `sellable_qty > 0` 的持仓执行止损。
4. **可配置阈值**：止损浮亏比例通过配置项传入，**不在代码中写死**，默认值为 5%（即 `-0.05`）。
5. **成交规则**：止损触发后，在**下一交易日**以**开盘价**全部清仓（与策略信号采用相同的 `next_open` 成交模式，避免未来函数）。
6. **日志记录**：止损卖出操作需通过 `logger.info` 记录，包含日期、股票代码、成本价、当前价、浮亏比例、卖出数量。

### 5.2 交互流程

```text
每日回测循环（日线）
│
├─ ① 开盘前：portfolio.before_trading(date) —— 解冻 T+1 持仓
├─ ② strategy.before_trading_start(context, data)
├─ ③ strategy.handle_data(context, data) —— 策略生成买卖信号
├─ ④ 【新增】止损检查：遍历 portfolio.positions
│       若 pos.sellable_qty > 0 且 profit_ratio < -threshold：
│           生成止损 Order(code, SELL, qty=sellable_qty)
│           加入当日 orders 队列
├─ ⑤ TradeEngine.execute_orders —— 撮合策略订单 + 止损订单
├─ ⑥ strategy.after_trading_end(context, data)
└─ ⑦ 记录当日 NAV
```

**关键时序说明**：
- 止损检查放在 `handle_data()` 之后、`execute_orders()` 之前。
- 这样设计的理由：策略当日信号（如金叉买入）与止损信号在同一日竞争撮合；若先执行止损，策略买入信号仍可在当日成交，资金使用效率最高。
- 止损使用市价单（`OrderType.MARKET`），与策略信号单一起进入撮合队列，统一遵守涨跌停、T+1、成交量限制。

## 6. 配置变更

在 `config/backtest.yaml` 中新增以下配置项：

```yaml
# 止损配置
stop_loss:
  enabled: true          # 是否启用全局止损
  threshold: 0.05        # 止损阈值：浮亏达到 5% 时触发（正数表示百分比）
```

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `stop_loss.enabled` | bool | `true` | 全局止损开关 |
| `stop_loss.threshold` | float | `0.05` | 止损触发阈值，0.05 表示浮亏达到 5%。必须为 **正数**，引擎内部取负值比较。 |

## 7. 不可改动的红线区域

1. **策略接口不可变**：`BaseStrategy.initialize()`、`handle_data()`、`before_trading_start()`、`after_trading_end()` 的签名与调用时机**不得修改**。所有现有策略文件（`double_ma.py`、`momentum.py`、`multi_factor.py`）**不应被修改**。
2. **Context 下单接口不可变**：`Context.order()`、`Context.pop_orders()` 的签名与行为不得变更。
3. **TradeEngine 撮合逻辑不可变**：`execute_orders()` 的撮合规则（涨跌停、T+1、滑点、费用）保持原样，止损单作为普通市价单进入撮合即可。
4. **Position 核心数据结构不可变**：`total_qty`、`sellable_qty`、`cost_price`、`_buy_records` 的语义与更新逻辑不得变更。允许新增辅助方法，但不可删除或重命名现有字段/方法。
5. **回测可复现性不可破坏**：相同配置、相同策略、相同数据，多次运行结果必须完全一致。

- [ ] 当 `enabled: false` 时，回测行为与修改前完全一致（同一策略、同一区间，NAV 曲线完全相同）。
- [ ] 当 `enabled: true`、`threshold: 0.05` 时，若某持仓当日收盘价相对成本价下跌 5% 或以上，系统会在下一交易日生成该股票的卖出订单。
- [ ] 当日买入的股票（`sellable_qty == 0`）不会被止损卖出。

### 9.2 测试用例

**用例 1：止损触发场景**
- **前置条件**：`stop_loss.enabled = true`，`stop_loss.threshold = 0.05`
- **输入**：持仓 `000001.SZ` 1000 股，成本价 10.00，当日收盘价 9.40（浮亏 6%）
- **修改前行为**：无止损机制，次日继续持仓
- **修改后预期行为**：
  - 当日收盘后检测到浮亏 6% ≥ 5%
  - 次日开盘前生成 `Order(code="000001.SZ", side=SELL, qty=1000)`
  - 次日以开盘价撮合卖出

**用例 2：未触及止损场景**
- **前置条件**：同上
- **输入**：持仓 `000001.SZ` 1000 股，成本价 10.00，当日收盘价 9.60（浮亏 4%）
- **修改后预期行为**：不触发止损，继续持有

**用例 3：T+1 当日买入不止损**
- **前置条件**：同上
- **输入**：当日盘中策略买入 `000001.SZ` 500 股，成交价 10.00，当日收盘价 9.00（浮亏 10%）
- **修改后预期行为**：
  - 当日收盘后检测到该持仓，但 `sellable_qty == 0`
  - 不生成止损订单
  - 下一交易日开盘后 `sellable_qty` 更新为 500，此时若收盘价仍为 9.00（或更低），再触发止损

使用 `DoubleMAStrategy` 进行回测对比：

## 10. 备注

1. **未来函数风险**：止损检查必须基于**当日已收盘后的价格**（收盘价）进行判断，卖出必须在**下一交易日**执行。绝不允许在当日 `handle_data()` 中基于当日收盘价生成并在当日成交，否则构成未来函数。
2. **与策略信号的优先级**：若策略在当日 `handle_data()` 中发出了买入信号，同时该股票的前一日持仓触发止损，则止损单与买入单会在同一日进入撮合队列。由于两者方向相反，最终净效果取决于具体数量，这是合理行为。
3. **止损阈值的边界**：`threshold` 为正数（如 0.05），引擎内部计算时取 `-threshold` 与 `profit_ratio` 比较。禁止配置为负数或零（可在引擎启动时校验并抛出 `ValueError`）。
4. **后续扩展**：未来可考虑支持"单笔独立止损"（追踪每一笔买入的独立成本，而非加权平均成本），以及"移动止盈/跟踪止损"，但不在本次需求范围内。
