## 2. 背景与动机

现有 ML 策略 `strategy/ml_stock_picker/` 是**单模型、固定 5 日调仓、Top-K 等权**结构，存在三个明确缺陷：

- **无独立卖出逻辑**：唯一的"卖"只能靠"跌出 Top-K"，对急跌或趋势反转响应慢
- **持有期固定**：5 日调仓不区分短期信号和中长期信号，浪费 long horizon 模型可能更稳的优势
- **无风险管理**：没有止损止盈、没有 regime 过滤，bear 市场满仓被动持有

本需求新增独立策略 `strategy/ml_multi_horizon_picker/`，**不动现有策略**，专门解决以上三点：

1. **多 horizon 买入模型**（1/5/10/20 天独立训练）→ 每日重打分，动态决定持有期
2. **独立卖出模型**（label=未来 5 日最大回撤 > 5%）→ 捕捉买入模型遗漏的非线性风险
3. **多重卖出触发 + regime 调制**：止损/追踪止盈/排名迟滞/卖出模型/horizon 到期/regime 缩仓

不实现的后果：当前 ML 选股策略对急跌缺乏响应（PRD_20260524_07 / 08 / 10 系列实测中已观察到回撤偏深），且无法验证"多 horizon 模型是否真比单 horizon 稳"。

回测影响：本需求**新增**策略，不改动已有任何回测路径。

## 5. 需求详情

### 5.1 多 horizon 买入模型

训练 **4 个独立 LightGBM 二分类模型**：

| 模型名 | 标签 horizon | label 规则 |
|---|---|---|
| `buy_h1` | 1 天 | 截面分位 top 30% → 1，bottom 30% → 0，其余丢弃 |
| `buy_h5` | 5 天 | 同上 |
| `buy_h10` | 10 天 | 同上 |
| `buy_h20` | 20 天 | 同上 |

特征：复用 `FeatureEngineer.feature_columns()` 的 17 维（与 DWS 表对齐，无需重新计算）。

输出：`prob_up_h1 / prob_up_h5 / prob_up_h10 / prob_up_h20 ∈ [0, 1]`。

### 5.2 独立卖出模型

训练 **1 个 LightGBM 二分类模型** `sell_v1`：

- **标签**：未来 5 天内 `(min_close - cost) / cost < -5%` → 1（应该卖），否则 0
- **特征**：17 维买入特征 + 5 维卖出风险特征：
  - `drawdown_from_high_20d`：当前价相对 20 日最高价的回撤
  - `drawdown_from_high_60d`：相对 60 日最高价
  - `vol_expansion`：std_5d / std_60d，> 1 表示波动率放大
  - `rsi_overbought_streak`：RSI > 70 连续天数
  - `dist_to_ma60`：(close - ma60) / ma60

输出：`prob_sell ∈ [0, 1]`。

### 5.3 市场状态（Regime）

输入：基准指数 `000300.SH` 日 K 线。

输出：`bull` / `neutral` / `bear` 三态，规则：

```
close > ma200 且 60d 实际波动率 < 历史 60d 波动率 80% 分位  →  bull
close > ma200 且 60d 实际波动率 >= 80% 分位                  →  neutral
close < ma200                                                →  bear
```

简单可调试，避开 HMM 收敛麻烦。

### 5.4 主策略交互流程

每个交易日（**日频调仓**）：

```
1. 计算 regime  →  确定 target_position_count（bull=N, neutral=0.7N, bear=0.3N）
                  和 stop_loss_pct（bull/neutral=5%, bear=3%）

2. 对全市场股票批量预测 4 个 horizon prob_up + 1 个 prob_sell

3. 主得分 score = max(prob_up_h5, prob_up_h10, prob_up_h20)   ← 跳 h1，太噪
   动态持有期 expected_holding = argmax_h h × prob_up_h        h ∈ {5, 10, 20}

4. 现有持仓逐个检查【6 个 sell trigger】（任一命中即卖）：
   a. 硬止损       : 现价 < cost × (1 - stop_loss_pct)
   b. 追踪止盈     : 现价 < 持仓期最高价 × (1 - trailing_stop_pct)   ← trailing_stop_pct=3%
   c. Horizon 到期 : 持有天数 >= expected_holding_at_buy
   d. 排名迟滞     : 连续 dropout_persistence_days(=2) 天不在 Top-2K 且持有 >= min_hold_days(=3)
   e. prob_up 兜底 : prob_up_h5 < min_prob_floor(=0.30) 且持有 >= min_hold_days
   f. 卖出模型     : prob_sell > sell_threshold(=0.70)

5. 卖出执行完后，按 target_position_count 排序 Top-N，
   未持仓且 prob_up_h5 >= min_buy_prob(=0.50) 的进入候选，
   等权分配剩余资金买入直到达到 target_position_count

6. bear regime 下额外：不开新仓，只允许补到 target_position_count（30% N）
```

### 5.5 持仓状态簿记

主策略需额外维护：
- `_position_entered_date[code]`：建仓日期，用于算 holding_days
- `_position_peak_price[code]`：持仓期最高收盘价，用于追踪止盈
- `_position_expected_horizon[code]`：建仓时 argmax horizon，用于 Horizon 到期判断
- `_rank_dropout_streak[code]`：连续不在 Top-2K 的天数

## 10. 备注

### 10.1 Lookahead Bias 风险点

| 风险点 | 防护 |
|---|---|
| 标签使用未来 N 日数据 | 训练专用，回测时不喂未来数据 |
| 回测时特征用了当日 close | OK，因为 `BacktestEngine` 默认信号 T → 成交 T+1 开盘 |
| Regime 计算用了截至当日的 MA200 | OK，使用 `t` 日及之前的数据 |
| 卖出模型的 cost 字段 | 训练时随机模拟"持仓 5 天前的价格"作为 cost；回测时用真实 cost_price |

### 10.2 训练数据成本

- 训练在本地 Mac M 系列即可，LightGBM 5 模型 × ~200 万样本 ≈ 30 分钟
- 不必动 GCE VM
- BigQuery 读取量：约 5 GB × 1 次 ≈ HK$2 查询费

### 10.3 v1 范围与后续可扩展

**v1 不做**：
- 多 horizon prob 的 stacking ensemble（直接 max 即可）
- Sell 模型用 LightGBM Quantile Regression 改成回归任务
- 用 RL 学动态 holding 而不是 argmax
- 跨市场状态训练（直接全样本训）
- 仓位 Kelly 优化

**v2 候选**（独立 PRD）：以上任一项。
