## 2. 背景与动机

当前 BigQuery 已采用单 dataset `ashare`，通过 `ods_` / `dwd_` / `dws_` / `ads_` 表前缀表达分层。PRD_11 将现有 GCS Parquet 作为 ODS external table；PRD_12 将 ODS 转换为完整 DWD native table，并让 `BigQueryDataSource` 可以读取日线行情、股票列表和板块成分数据。

但策略侧仍然在每次回测时临时计算大量滚动特征：

- `double_ma` 需要短长均线。
- `ml_stock_picker` 需要收益率、量能、波动率、RSI、MACD、价格位置等特征。
- `volatility_timing` / `regime_switching` 需要指数动量、波动率和量能观测变量。
- `portfolio_optimization` / `rl_portfolio` 需要多资产收益率、波动率、协方差等组合输入。
- `pair_trading` 需要配对价格、收益率和价差统计。

如果这些特征全部在 Python 回测循环中重复计算，会导致：

- 每次回测重复扫描 DWD 行情表。
- 策略训练、信号检查和回测口径不一致。
- 后续虚拟盘或批量回测难以复用同一套特征。

本 PRD 的目标是基于当前唯一正式数据源 `gs://data-aquarium/a-share/standardized_parquet/` 已生成的 `ashare.dwd_*` 表，建设第一版 DWS 特征层和 ADS 信号层，并把数据实际跑出来。

## 5. 需求详情

### 5.1 功能目标

新增并运行以下 BigQuery 管道命令：

- `transform-dws`：从 `ashare.dwd_*` 生成 `ashare.dws_*` 特征层。
- `audit-dws`：检查 DWS 表存在、非空、核心字段完整。
- `transform-ads`：从 `ashare.dws_*` 生成 `ashare.ads_*` 信号层。
- `audit-ads`：检查 ADS 表存在、非空、核心字段完整。

第一版 DWS 表：

| 表 | 来源 | 目标 |
| --- | --- | --- |
| `dws_equity_daily_features` | `dwd_fact_equity_kline_1d` | 股票日线技术特征，供 ML 选股、动量和截面排序使用 |
| `dws_fund_daily_features` | `dwd_fact_fund_kline_1d` | ETF/基金日线均线与收益特征，供双均线和组合策略使用 |
| `dws_index_daily_features` | `dwd_fact_index_kline_1d` | 指数动量、波动、量能特征，供择时和市场状态策略使用 |
| `dws_portfolio_asset_returns_1d` | 股票/基金/指数 DWS | 多资产收益率和波动率矩阵基础表 |
| `dws_board_component_latest` | `dwd_fact_board_component_1d` | 板块最新成分股快照，供配对和行业池筛选使用 |
| `dws_pair_candidate_stats` | `dws_equity_daily_features` | 股票池内配对收益相关性、beta 和价差统计 |

第一版 ADS 表：

| 表 | 来源 | 目标 |
| --- | --- | --- |
| `ads_signal_double_ma_1d` | `dws_fund_daily_features` | MA5/MA20 金叉死叉信号 |
| `ads_signal_ml_stock_picker_1d` | `dws_equity_daily_features` | 基于现有 ML 特征的截面排序候选信号，模型分数暂以可解释启发式 proxy 生成 |
| `ads_signal_volatility_timing_1d` | `dws_index_daily_features` | 指数波动率择时仓位建议 |
| `ads_signal_regime_switching_1d` | `dws_index_daily_features` | 非 HMM 依赖的市场状态 proxy，用于后续 HMM 训练/验证 |
| `ads_portfolio_risk_snapshot_1d` | `dws_portfolio_asset_returns_1d` | 按日期和资产类型汇总的组合风险快照 |

### 5.2 特征口径

`dws_equity_daily_features` 必须包含并尽量对齐 `FeatureEngineer.feature_columns()`：

- 收益率：`return_1d`、`return_5d`、`return_10d`、`return_20d`
- 量能：`volume_ma5_ratio`、`volume_ma20_ratio`、`amount_ma5_ratio`
- 波动：`std_5d`、`std_20d`、`std_ratio`
- RSI：`rsi_14`
- MACD：`macd_diff`、`macd_signal`、`macd_hist`
- 价格位置：`close_to_high_20d`、`close_to_ma5`、`close_to_ma20`

基金和指数 DWS 可以保留同类核心字段，但不要求完全等同股票特征。组合/择时策略至少需要：

- `return_1d`
- `return_20d`
- `ma_5`
- `ma_20`
- `volatility_20`
- `amount_ma20_ratio`

所有滚动特征必须只使用当前日及历史数据，不能使用未来数据。

### 5.3 ADS 信号口径

| 信号表 | 关键规则 |
| --- | --- |
| `ads_signal_double_ma_1d` | `ma_5 > ma_20` 为多头，`ma_5 < ma_20` 为空仓；`signal` 取 `1/0` |
| `ads_signal_ml_stock_picker_1d` | 使用 DWS 特征生成 `score_proxy`，按每日截面排序，`rank <= 50` 给出候选买入信号 |
| `ads_signal_volatility_timing_1d` | 指数 `return_20d > 0` 且 `volatility_20` 未处于高波区间时建议高仓位，否则降仓 |
| `ads_signal_regime_switching_1d` | 用 `return_20d`、`volatility_20` 和 `amount_ma20_ratio` 生成 `bull/sideways/bear` proxy 状态 |
| `ads_portfolio_risk_snapshot_1d` | 按日期和资产类型汇总资产数量、平均收益、平均波动率和极端波动资产数 |

ADS 第一版是“信号候选表”，不直接修改策略下单逻辑。

### 5.4 交互流程

```text
ashare.dwd_* audit PASS
  -> transform-dws
  -> audit-dws
  -> transform-ads
  -> audit-ads
  -> smoke query 输出表数量与行数
  -> ARCHITECTURE.md 同步
```

失败时：

```text
某个 DWS/ADS 表缺字段或空表
  -> audit 失败
  -> 不声明完成
  -> 修复 SQL 后重跑对应 transform
```

## 10. 备注

- 第一版 `ads_signal_ml_stock_picker_1d` 的 `score_proxy` 不是训练好的 ML 模型输出，只是把现有可解释特征统一落表，便于后续训练、特征监控和模型替换。
- 第一版配对统计只覆盖配置中的样例股票池，避免对全市场两两组合产生过高扫描成本。
- `fact_financial_indicator` 当前 DWD 表由于 ODS safe raw schema 限制，暂不进入 DWS 基本面因子；后续需要单独 PRD 做财务表字段级映射。
