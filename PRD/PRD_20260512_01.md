## 2. 背景与动机

当前 `AKShareDataSource.get_bars()` 的缓存逻辑存在缺陷：只要本地缓存文件存在且非空，就直接返回缓存数据，**不检查缓存数据是否覆盖了用户请求的日期范围**。这导致以下问题：

- 首次请求 2022-2023 年数据时，框架拉取了完整数据并写入缓存。
- 后续某次短区间请求（如 2021-11 ~ 2021-12）写入同一缓存文件，**覆盖了完整数据**。
- 再次请求 2022-2023 年数据时，`get_bars()` 读取到只有 25 行的旧缓存，直接返回，导致策略 `get_price()` 拿到空表，无法计算均线和交易信号。

**不修复的后果**：
- 任何因测试、调试产生的短区间缓存，都会永久破坏该标的的后续回测。
- 用户必须手动删除缓存文件才能恢复，体验极差。
- 已严重阻塞 510300.SH 的 ETF 回测验证。

### 4.2 `data_layer/local_storage.py` — `load_bars()`

```python
def load_bars(
    self,
    code: str,
    start_date: Optional[str] = None,
    end_date: Optional[str] = None,
    period: str = "daily",
    fmt: str = "parquet",
) -> pd.DataFrame:
    path = self._bar_path(code, period, fmt)
    if not path.exists():
        return pd.DataFrame()

    if fmt == "parquet":
        df = pd.read_parquet(path)
    else:
        df = pd.read_csv(path)

    if "date" not in df.columns:
        return df

    if start_date:
        df = df[df["date"] >= start_date]
    if end_date:
        df = df[df["date"] <= end_date]
    return df.reset_index(drop=True)
```

> **注意**：`load_bars` 已经做了日期范围过滤，但 `get_bars` 判断 `not cached.empty` 后就直接返回了。如果缓存整体非空但过滤后为空（即请求区间完全不在缓存范围内），`load_bars` 会返回空表，`get_bars` 会继续走 AKShare 拉取。真正的问题是：**缓存覆盖了请求区间的一部分，但没有完全覆盖**，此时 `load_bars` 返回部分数据，`get_bars` 直接返回，导致数据缺失。

## 5. 需求详情

### 5.1 功能目标

1. **缓存覆盖范围检查**：`get_bars()` 读取本地缓存后，必须验证缓存数据的日期范围是否**完全覆盖**用户请求的 `[start_date, end_date]` 区间。
2. **缺失区间补充拉取**：若缓存未完全覆盖，计算缺失的日期子区间，调用 AKShare 接口补充拉取，与缓存数据合并后更新本地缓存。
3. **向后兼容**：保持现有缓存文件格式（Parquet/CSV）不变，不引入新的元数据文件。
4. **性能优化**：优先读取缓存，仅对缺失区间发起网络请求，避免重复拉取已缓存数据。

### 5.2 覆盖判定逻辑

```python
def _is_fully_covered(cached_df: pd.DataFrame, start_date: str, end_date: str) -> bool:
    """判断缓存数据是否完全覆盖请求区间。"""
    if cached_df.empty:
        return False
    cached_min = cached_df["date"].min()
    cached_max = cached_df["date"].max()
    # 注意：date 列可能为 str 或 int，统一转为 str 比较
    return str(cached_min) <= str(start_date) and str(cached_max) >= str(end_date)
```

### 5.3 缺失区间补充流程

```text
用户请求 get_bars(code, start=20220101, end=20231231)
│
├─ 1. 读取完整缓存文件（不做日期过滤）
│   └─ cached = storage.load_bars_raw(norm_code, period)  # 新增原始读取接口
│
├─ 2. 判定覆盖范围
│   └─ 若 _is_fully_covered(cached, 20220101, 20231231) → 直接返回过滤后的缓存
│   └─ 若缓存为空 → 走完整 AKShare 拉取
│   └─ 若缓存未完全覆盖 → 进入 3
│
└─ 3. 补充拉取缺失区间
    ├─ 计算缺失起点：missing_start = min(请求start, 缓存min)
    ├─ 计算缺失终点：missing_end   = max(请求end,   缓存max)
    ├─ 调用 AKShare 拉取 [missing_start, missing_end] 的完整数据
    ├─ 与缓存数据合并（去重，以 AKShare 数据为准）
    └─ 写入本地缓存，返回过滤后的结果
```

> **简化方案**：由于 AKShare 免费接口没有严格的流量限制，且单只股票日K数据量很小（2年仅约 500 行），可以直接拉取完整区间 `[min(start_date, cached_min), max(end_date, cached_max)]`，与缓存合并后落盘。无需精确计算"空洞"区间。

## 8. 备注

1. **数据合并策略**：缓存数据与 AKShare 新拉取数据按 `date` 列合并，AKShare 数据优先级更高（覆盖缓存中的同日期记录）。使用 `pd.concat([cached, new]).drop_duplicates(subset=["date"], keep="last")`。
2. **异常处理**：若补充拉取失败（网络不可用），fallback 行为：返回缓存中已有的部分数据 + 日志警告，而非直接报错，保证回测可用性。
3. **与 P0-1（日期解析 bug）的关系**：两者独立。P0-1 影响回测结果展示，本 PRD 影响回测数据获取的完整性。
