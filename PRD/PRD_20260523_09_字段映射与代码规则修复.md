## 2. 背景与动机

用户已确认后续不重生成 `standardized_parquet_v2`，只使用当前这一版 GCS 数据：

```text
gs://data-aquarium/a-share/standardized_parquet/
```

因此，字段标准化不能再以前置重跑 Parquet 为前提。当前 GCS Parquet 应作为唯一正式输入源装载到 `ashare.ods_*`，字段标准化、资产代码字段分流和严格类型转换应在 BigQuery ODS/DWD 阶段完成。

需要修复的设计问题：

| 编号 | 问题 | 新处理方式 |
| --- | --- | --- |
| E1 | 财务表若使用 `report_period` 作为业务可见日期，会引入 Lookahead Bias | DWD transform 必须优先使用公告日期字段，缺失则进入错误审计或标记不可用 |
| E4 | 北交所代码可能被旧逻辑错归 SZ | 在 DWD transform / 代码规范化工具中统一补 `.BJ` 规则 |
| E7 | 现有数据中不同资产可能都落在 `security_code` 或中文代码列 | DWD 层按目标表映射为 `equity_code` / `fund_code` / `index_code` / `board_code` |
| S1 | ODS 可能保留中文或贴源字段 | 接受 ODS 贴源；DWD 负责标准英文 schema |

不解决会导致 `BigQueryDataSource` 无法稳定读取 `dwd_*` 表，也会让股票、基金、指数、板块代码语义混在一起。

```python
def normalize_security_code(value: object) -> str | None:
    text = "" if value is None else str(value).strip().upper()
    if not text:
        return None
    text = text.replace("_", ".")
    if re.fullmatch(r"\d{6}", text):
        if text.startswith(("5", "6", "9")):
            return f"{text}.SH"
        return f"{text}.SZ"
    if re.fullmatch(r"(SH|SZ|BJ)\d{6}", text):
        return f"{text[2:]}.{text[:2]}"
    return text
```

## 5. 需求详情

### 5.1 功能目标

- 不重生成 Parquet。
- 不创建 `standardized_parquet_v2/`。
- 保留当前 GCS prefix 作为正式输入源。
- 新增字段映射配置，供 DWD transform 使用。
- 股票事实表字段统一命名为 `equity_code`。
- `dim_security` 保留 `security_code`，因为它是多资产证券维表。
- 基金、指数、板块事实表分别用 `fund_code`、`index_code`、`board_code`。
- 北交所代码规则统一纳入映射/规范化逻辑。
- 财务表在 DWD 层严格区分 `announcement_date` 与 `report_period`。

### 5.2 字段映射配置

建议在 `gcs_to_bigquery/config.yaml` 中新增：

```yaml
field_mappings:

    基金代码: fund_code
    基金交易代码: fund_code

    板块代码: board_code
    成分股票代码: equity_code
    日期: date_raw
    交易日期: date_raw
    公告日期: announcement_date_raw
    实际公告日期: actual_announcement_date_raw
    报告期: report_period_raw
    开盘: open_raw
    收盘: close_raw
    最高: high_raw
    最低: low_raw
    成交量: volume_raw

  per_table:

  report_period_is_not_visible_date: true
```

### 5.3 代码规范化规则

股票代码规范化应支持：

```text
430xxx -> 430xxx.BJ
83xxxx -> 83xxxx.BJ
87xxxx -> 87xxxx.BJ
88xxxx -> 88xxxx.BJ
920xxx -> 920xxx.BJ
5xxxxx / 6xxxxx / 9xxxxx（非 92）-> .SH
其他 6 位数字 -> .SZ
SH000001 -> 000001.SH
SZ000001 -> 000001.SZ
BJ430139 -> 430139.BJ
```

字段语义：

| 表类型 | DWD 字段 |
| --- | --- |
| 股票事实表 | `equity_code` |
| 基金事实表 | `fund_code` |
| 指数事实表 | `index_code` |
| 板块事实表 | `board_code` |
| 多资产维表 `dim_security` | `security_code` |
| 板块成分表 | `board_code` + `equity_code` |

### 5.4 交互流程

```text
现有 GCS Parquet
  -> create-ods-external 创建 ashare.ods_* 外部表（贴源）
  -> transform-dwd 读取 field_mappings
  -> 生成 ashare.dwd_* 标准字段
  -> audit-dwd 检查代码字段、日期字段和类型转换
```

## 6. 配置变更

| 配置项 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `field_mappings.common` | MAP | 无 | 通用中英字段候选映射 |
| `field_mappings.per_table.<table>.code_column` | STRING | 按表配置 | DWD 目标代码字段 |
| `field_mappings.per_table.<table>.source_candidates` | LIST | 按表配置 | ODS 可能存在的源字段候选 |
| `financial_date_policy.strict_visible_date` | STRING | `announcement_date` | 财务表可见日期来源 |
| `financial_date_policy.report_period_is_not_visible_date` | BOOL | `true` | 防止用报告期替代公告日期 |

不新增 `data_transfer/column_name_map.yaml`，避免误导后续以为需要重生成 Parquet。

## 7. 不可改动的红线区域

- 不重生成当前 GCS Parquet。
- 不创建或引用 `standardized_parquet_v2/`。
- 不删除 `gs://data-aquarium/a-share/standardized_parquet/`。
- 不修改 `data_transfer/prepare_parquet_to_gcs.py` 作为本 PRD 的交付目标。
- 不把股票事实表继续命名为 `security_code`。
- 不把 `dim_security.security_code` 改成 `equity_code`，因为维表是多资产统称。
- 不用 `report_period` 作为财务数据可见日期。

## 9. 验收标准

- `gcs_to_bigquery/config.yaml` 中存在 `field_mappings`，且 P0 表全部有代码字段映射。
- `fact_equity_kline_1d` 的 DWD 目标代码字段为 `equity_code`。
- `dim_security` 的目标代码字段为 `security_code`。
- `fact_board_component_1d` 同时包含 `board_code` 和 `equity_code`。
- 北交所代码测试通过。
- 财务表没有把 `report_period` 当作 DWD `date`。
- 不出现 `standardized_parquet_v2`。
