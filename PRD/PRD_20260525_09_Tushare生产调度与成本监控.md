## 2. 目标

在 Tushare 数据采集、BigQuery 分层和模型训练链路具备基础能力后，建立可长期运行的生产调度、成本监控和失败处理机制。

## 3. 调度范围

生产调度包括：

- 每日 Tushare 增量采集。
- 每日 GCS raw 到 BigQuery 加载。
- 每日数据质量审计。
- 每日信号或候选池生成。
- 月度模型重训。
- 失败重试和人工排查入口。

## 4. Cloud Run Job

建议保留独立 Job：

```text
tushare-ingest-p0
tushare-ingest-p1
tushare-ingest-p2
tushare-gcs-to-bq
tushare-dwd-dws-build
tushare-monthly-train
```

第一版可先用单个通用 Job 加环境变量区分任务，后续再拆分。

## 5. 调度策略

每日：

1. 盘后拉取日线、日频指标、涨跌停、停牌、资金流等。
2. 写入 GCS raw。
3. 从 raw 更新 ODS/DWD/DWS。
4. 执行数据质量检查。
5. 生成下一交易日候选池。

月度：

1. 使用最新完整月数据重训。
2. 生成模型 registry。
3. 运行样本外回测。
4. 通过阈值后标记为 candidate 或 production。

## 6. 成本监控

监控对象：

- Cloud Run Job 执行时间和失败次数。
- GCS 存储量和对象数。
- BigQuery 存储量。
- BigQuery 查询扫描量。
- 训练任务 CPU/内存/运行时间。

成本原则：

- GCS raw 长期保留，但可按生命周期策略转冷存储。
- BigQuery 大表必须分区。
- 训练 SQL 必须限制日期范围。
- 不把分钟线、Tick、全文语料直接全量物化进 BigQuery。

## 7. 告警

第一版最低要求：

- Job 失败可在 Cloud Run 日志中定位。
- Manifest summary 记录失败数量。
- 数据质量审计产出失败状态。

后续可增加：

- 邮件或 IM 告警。
- BigQuery 成本日预算告警。
- GCS 对象数异常增长告警。
- Tushare 接口失败率告警。

## 8. 凭据

Tushare token：

- 本地使用环境变量 `TUSHARE_TOKEN`。
- Cloud Run 使用 Secret Manager。
- 不写入 git。
- 不打印到日志。

GCP：

- 使用 `data-aquarium`。
- Cloud Run service account 仅授予必要 GCS/BQ/Secret 权限。

## 9. 验收标准

1. 能通过 Cloud Run Job 完成每日增量采集。
2. 每次运行有 manifest summary。
3. 失败后可通过 checkpoint 续跑。
4. BigQuery 加载和特征构建有日志和审计结果。
5. 成本查询能按天汇总 Cloud Run、GCS、BigQuery 费用。
6. token 不出现在代码、配置样例和日志中。
