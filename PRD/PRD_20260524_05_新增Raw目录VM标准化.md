## 2. 背景与动机

当前 GCS 已出现四类新增原始目录，其中前三类仍在上传中，`指数数据` 目录已经具备较完整的目录结构但内部形态更复杂：

- `gs://data-aquarium/a-share/raw/source_snapshot=20260523/开盘啦榜单/`
- `gs://data-aquarium/a-share/raw/source_snapshot=20260523/龙虎榜席位/`
- `gs://data-aquarium/a-share/raw/source_snapshot=20260523/资金流向/`
- `gs://data-aquarium/a-share/raw/source_snapshot=20260523/指数数据/`

只读抽样结果：

- `开盘啦榜单`：当前约 2032 个对象，其中 CSV 2032 个、说明 txt 1 个；文件范围已到 `20260522.csv`。
- `龙虎榜席位`：当前约 967 个 CSV，上传还停在 2016 年附近。
- `资金流向`：当前约 524 个 CSV，上传还停在 2013 年附近。
- `指数数据`：当前约 1167 个对象，其中 CSV 735 个、zip 432 个。根目录包含 `指数日线行情.zip`、`指数周线行情.zip`、`指数月线行情.zip`、`中信行业日线行情.zip`、`申万行业日线行情.zip` 和 7 个 `指数基本信息_*.csv`；子目录包含上交所/中证/深交所指数成分 zip、中信/申万行业分类、申万行业成分每日更新、大盘指数每日指标，以及 2025-09 至 2026-05 的增量日线 CSV。
- `standardized_parquet` 已有 `dim_index`、`fact_index_kline_1d`、`fact_index_kline_1w`、`fact_index_kline_1mo`、`fact_board_kline_*` 等表。因此本需求不能把普通指数 K 线全量/增量直接追加到同名表，避免 BigQuery ODS external table 后续读到重复行。
- 前三类新增目录第一版只处理 CSV，跳过 txt/zip；`指数数据` 第一版按子前缀精确同步 CSV 或 zip，保留行业、成分和指标类新增价值数据，排除与现有指数 K 线表高度重叠的普通指数 K 线文件。

样例字段：

- 开盘啦榜单：`日期`、`代码`、`名称`、`初次涨停时间`、`最后涨停时间`、`炸板时间`、`跌停时间`、`涨停原因`、`标签`、`板块`、`主力净额(元)`、`N连板` 等。
- 龙虎榜席位：`日期`、`代码`、`股票名称`、`买卖类型`、`营业部名称`、`买入额(元)`、`卖出额(元)`、`净成交额(元)`、`上榜理由`。
- 资金流向：`日期`、`代码`、`名称`、小/中/大/特大单买卖量额、`净流入量(手)`、`净流入额(万元)`。
- 指数基本信息：`指数代码`、`简称`、`市场`、`发布方`、`指数类别`、`基期`、`基点`、`发布日期`。
- 指数成分 zip：zip 内每个指数一个 CSV，字段为 `指数代码`、`成分股票代码`、`交易日期`、`权重`。
- 中信/申万行业分类：行业层级 CSV 字段为 `指数代码`、`行业名称`、`行业分级`、`行业代码`、`是否发布指数`、`父级代码`；中信成分历史字段为一二三级行业代码/名称、`股票代码`、`股票名称`、`纳入日期`、`剔除日期`、`是否最新`。
- 行业日线：中信行业日线字段为 `指数代码`、`交易日期`、OHLC、涨跌、成交量/成交额；申万行业日线额外包含 `行业名称`、`市盈率`、`市净率`、`流通市值(万元)`、`总市值(万元)`。
- 大盘指数每日指标：`指数代码`、`交易日期`、`总市值(元)`、`流通市值(元)`、`总股本(股)`、`流通股本(股)`、`自由流通股本(股)`、`换手率`、`市盈率`、`市盈率TTM`、`市净率`。

期望行为：上传完成后，在一台 VM 上把这些新增 GCS raw 文件同步到本地 SSD，沿用现有 `prepare_parquet_to_gcs.py` 生成 month-partitioned Parquet，并上传到当前正式标准化前缀 `gs://data-aquarium/a-share/standardized_parquet/`。本需求只准备架构和代码，不启动 VM、不上传未完成数据、不写 BigQuery。

## 5. 需求详情

### 功能目标

1. 新增三类 raw 目录到标准化表的映射：
   - `开盘啦榜单` -> `fact_kpl_board_1d`
   - `龙虎榜席位` -> `fact_dragon_tiger_seat_1d`
   - `资金流向` -> `fact_money_flow_1d`
2. 新增 `指数数据` 中非重复价值数据到标准化表的映射：
   - `指数基本信息_*.csv` -> `dim_index_profile`
   - `上交所指数成分` / `中证指数成分` / `深交所指数成分` -> `fact_index_component_1d`
   - `中信行业分类_行业层级图.csv` -> `dim_citic_industry`
   - `中信行业分类_成分股_全部_CITIC.csv` -> `fact_citic_industry_component_history`
   - `申万行业分类/*.csv` -> `dim_sw_industry`
   - `申万行业成分_每日更新/*.csv` -> `fact_sw_industry_component_1d`
   - `中信行业日线行情.zip` 与对应增量 CSV -> `fact_citic_industry_kline_1d`
   - `申万行业日线行情.zip` 与对应增量 CSV -> `fact_sw_industry_kline_1d`
   - `大盘指数每日指标/*.csv` 与对应增量 CSV -> `fact_index_market_indicator_1d`
3. 明确跳过与既有标准化表高度重叠的普通指数行情：
   - 跳过根目录 `指数日线行情.zip`、`指数周线行情.zip`、`指数月线行情.zip`。
   - 跳过 `指数数据/增量数据/指数日线行情/`。
   - 原因：当前 `gs://data-aquarium/a-share/standardized_parquet/` 已有 `fact_index_kline_1d`、`fact_index_kline_1w`、`fact_index_kline_1mo`。直接追加会造成同一 `index_code + date` 的重复读取；后续如需补缺口，应另写“按主键去重/替换”的补数据 PRD。
4. 新增 `sync-raw` 命令：
   - 从配置指定的 GCS raw prefix 同步允许的 CSV/zip 到 VM 本地 SSD。
   - 支持每个 include prefix 单独设置 suffix，例如前三个目录只同步 `.csv`，指数成分和行业历史行情可同步 `.zip`。
   - 保留源目录结构，方便 `classify()` 继续通过目录名识别表。
   - 跳过未显式纳入的 txt、rar、7z、普通指数行情 zip 等对象。
   - 本地同路径且 size 一致时跳过，支持上传未完成期间反复重跑。
   - 写入 raw sync manifest，便于检查同步数量和失败点。
   - 支持 `ASHARE_USE_GCLOUD_ACCESS_TOKEN=1`，在 ADC 不可用时复用 `gcloud auth print-access-token`。
5. 新增 VM 专用配置：
   - 输入 GCS：`a-share/raw/source_snapshot=20260523/{开盘啦榜单,龙虎榜席位,资金流向,指数数据}`
   - 本地 raw：`/mnt/localssd/raw_incremental/source_snapshot=20260523`
   - 本地 parquet：`/mnt/localssd/parquet_incremental/source_snapshot=20260523`
   - 工作目录：`/mnt/localssd/work/raw_incremental_20260523`
   - 输出 GCS：`a-share/standardized_parquet`
6. 对 `fact_sw_industry_component_1d` 使用文件名日期作为快照 `date`，避免把 `纳入日期` 误当分区日期，导致每日快照语义丢失和跨文件重复堆积。
7. 不在本需求中创建 BigQuery ODS/DWD/DWS 表；后续等 Parquet 产物完成并 audit 后另写 PRD。

### 交互流程

```text
本地继续上传 raw CSV 到 GCS
  -> 等 GCS raw 文件数量稳定
  -> VM: sync-raw
       GCS raw CSV/选定 zip -> /mnt/localssd/raw_incremental/source_snapshot=20260523
  -> VM: build
       本地 raw CSV/zip 内 CSV -> 本地 month-partitioned Parquet
  -> VM: audit
       校验本地 parquet manifest / 路径 / row count
  -> VM: upload
       上传新增 fact_* / dim_* 表到 gs://data-aquarium/a-share/standardized_parquet/
  -> VM: audit --remote
       校验远端 parquet 路径与数量
```

## 6. 配置变更

新增 `data_transfer/cloud_new_raw_parquet_config.yaml`：

| 配置项 | 类型 | 默认值 | 作用 |
|---|---|---|---|
| `raw_gcs.source_prefix` | string | `a-share/raw/source_snapshot=20260523` | GCS raw 根前缀 |
| `raw_gcs.include_items` | list[object] | 新增目录和指数子前缀 | 每个前缀独立声明同步 suffix |
| `raw_gcs.include_items[].suffixes` | list[string] | `.csv` 或 `.zip` | 前三类 raw 只取 CSV；指数成分/行业历史行情按需取 zip |

| `parquet_root` | string | `/mnt/localssd/parquet_incremental/source_snapshot=20260523` | VM 本地 Parquet 输出 |
| `gcs.prefix` | string | `a-share/standardized_parquet` | 标准化 Parquet 正式输出前缀 |

## 7. 不可改动的红线区域

- 不删除、不修改当前 GCS raw prefix 中任何对象。
- 不把普通指数日/周/月 K 线全量 zip 或普通指数日线增量 CSV 追加进既有 `fact_index_kline_*` 表。
- 不全量同步 `指数数据/`；只能同步 `include_items` 中列出的子前缀，减少与既有 `standardized_parquet` 的重复。
- 前三类新增目录不处理 zip 内 CSV，避免与同名 CSV 重复入库；指数成分和行业历史行情 zip 是本需求显式允许的例外。
- 不覆盖或清空旧的 `/mnt/localssd/raw`、`/mnt/localssd/parquet`、`/mnt/localssd/work/table_manifests`。
- 不改已有 36 张表的输出路径；对 `指数数据` 新增优先分类规则，防止误落到已有 `fact_index_kline_*`。
- 不在本需求中写 BigQuery 表。
- 不改变已有回测引擎、策略、数据源接口。
