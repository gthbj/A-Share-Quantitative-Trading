## 2. 背景与动机

当前框架的回测可视化输出（累计收益曲线、回撤曲线、月度收益热力图）存在严重的显示异常：折线图中出现大面积水平直线段，月度热力图中大量月份显示为 0.0%。这一问题已导致用户无法正确判断策略的真实收益走势与回撤节奏，严重影响回测报告的可用性。

**不修复的后果**：
- 回测报告中的收益曲线、回撤曲线失真，用户无法直观判断策略表现。
- 月度收益热力图中大量月份被折叠为同一时间点，导致 0.0% 的虚假填充。
- 后续所有回测（无论策略、标的、频率）的可视化输出均受此 bug 影响，属于框架级缺陷。

## 4. 关键文件路径与现有函数签名

### 4.1 `engine/backtest.py` — `_build_result_df()`

```python
# engine/backtest.py
class BacktestEngine:
    def _build_result_df(self) -> pd.DataFrame:
        """将回测记录整理为 DataFrame。"""
        if not self.records:
            return pd.DataFrame()
        df = pd.DataFrame(
            [
                {
                    "date": r.date,
                    "nav": r.nav,
                    "cash": r.cash,
                }
                for r in self.records
            ]
        )
        df["returns"] = df["nav"].pct_change().fillna(0)
        df["cumulative_returns"] = (1 + df["returns"]).cumprod() - 1
        # 分钟级时间戳可能为 YYYYMMDDHHMM，根据长度区分解析
        raw_dates = df["date"].astype(str)
        df["date"] = pd.to_datetime(raw_dates, format="%Y%m%d%H%M", errors="coerce")
        # 对解析失败的（日线 YYYYMMDD 或长度不足），fallback 到 YYYYMMDD 格式
        mask = df["date"].isna()
        if mask.any():
            df.loc[mask, "date"] = pd.to_datetime(
                raw_dates[mask].str.slice(0, 8), format="%Y%m%d", errors="coerce"
            )
        df.set_index("date", inplace=True)
        return df
```

## 5. 需求详情

### 5.1 功能目标

1. **根治日期解析错误**：彻底移除依赖 `errors='coerce'` 的模糊解析模式，根据日期字符串长度显式选择解析器，确保 `YYYYMMDD` 和 `YYYYMMDDHHMM` 两种格式均能被正确解析。
2. **杜绝重复索引**：解析后的 `DatetimeIndex` 中，同一真实日期（或同一分钟 Bar）只能出现一次，禁止多条记录被折叠到同一个错误时间戳。
3. **向后兼容**：修复后的 `_build_result_df()` 必须同时兼容**日线回测**（`date` 格式为 `YYYYMMDD`）和**分钟级回测**（`date` 格式为 `YYYYMMDDHHMM`）。
4. **异常处理**：若遇到非预期长度的日期字符串（既非 8 位也非 12 位），应抛出明确的 `ValueError`，而非静默解析为错误值。
5. **无需修改下游消费端**：`plotter.py`、`report.py`、`metrics.py` 等消费模块不感知本次修复，仅需 `nav_df.index` 恢复正常即可。

### 5.2 根因分析

当前代码的问题在于 `pd.to_datetime(raw_dates, format='%Y%m%d%H%M', errors='coerce')` 的调用：

- 对于 `YYYYMMDD`（8 位）字符串，`format='%Y%m%d%H%M'` 理论上应返回 `NaT`（因为长度不匹配 12 位）。
- 但在 Python 3.9 + pandas 2.3.3 环境下，`strptime('20231218', '%Y%m%d%H%M')` 不会抛出异常，而是被**错误解析**为 `2023-01-02 01:08:00`。
- 这导致大量不同日期的记录被映射到同一个时间戳（如 `2023-01-02`），matplotlib 画线时把这些点连在一起，表现为**水平线段**。
- 同时，真正解析失败的记录 fallback 到 `%Y%m%d` 后，与错误解析的记录混在一起，进一步加剧了索引混乱。

**验证命令**：
```python
>>> pd.to_datetime('20231218', format='%Y%m%d%H%M', errors='coerce')
2023-01-02 01:08:00   # 预期应为 NaT
```

### 5.3 修复方案

**推荐方案：按长度显式路由（简单、可靠、零依赖）**

```python
raw_dates = df["date"].astype(str)
lengths = raw_dates.str.len()

# 初始化结果列
df["date"] = pd.NaT

# 8 位：日线 YYYYMMDD
mask8 = lengths == 8
if mask8.any():
    df.loc[mask8, "date"] = pd.to_datetime(
        raw_dates[mask8], format="%Y%m%d", errors="coerce"
    )

# 12 位：分钟线 YYYYMMDDHHMM
mask12 = lengths == 12
if mask12.any():
    df.loc[mask12, "date"] = pd.to_datetime(
        raw_dates[mask12], format="%Y%m%d%H%M", errors="coerce"
    )

# 异常长度
invalid = ~(mask8 | mask12)
if invalid.any():
    bad = raw_dates[invalid].iloc[0]
    raise ValueError(f"无法识别的日期格式（长度既非8也非12）: {bad}")

df.set_index("date", inplace=True)
```

**备选方案：正则预判断（更严谨，但过度设计）**

```python
import re
# 8 位纯数字 → 日线
# 12 位纯数字 → 分钟线
# 其他 → 报错
```

> **决策**：推荐方案 A。因为 `DailyRecord.date` 的写入端（`_run_daily` 和 `_run_intraday`）已严格保证格式为纯数字 `YYYYMMDD` 或 `YYYYMMDDHHMM`，无需引入正则的复杂度。

## 10. 备注

1. **为什么 pandas 的 `errors='coerce'` 在这里不可靠**：`pd.to_datetime('20231218', format='%Y%m%d%H%M', errors='coerce')` 在 pandas 2.3.3 + Python 3.9 环境下，不会返回 `NaT`，而是被底层 `strptime` 解析为 `2023-01-02 01:08:00`。这是 `strptime` 对长度不足输入的**未定义行为**，不应依赖。显式按长度路由是唯一能保证正确性的方案。
2. **与 P0-2（止损 lookahead bias）的关系**：P0-2 影响回测的**数值正确性**（未来函数），P0-1 影响回测结果的**展示正确性**（日期索引）。两者独立，修复顺序不分先后。
3. **分钟级索引精度**：当前分钟级回测的时间戳精度为 `YYYYMMDDHHMM`（12 位），无秒级精度。若未来需要支持秒级或 tick 级回测，需同步扩展日期格式与解析逻辑，不在本次需求范围内。
