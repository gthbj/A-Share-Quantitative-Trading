## 2. 背景与动机

用户已确认当前只使用一版 GCS Parquet：

```text
gs://data-aquarium/a-share/standardized_parquet/
```

ODS 的定位是贴源层。如果再把这批 Parquet load 成 BigQuery native ODS 表，会产生两份存储：

```text
GCS Parquet 一份 + BigQuery ODS native 表一份
```

这与 ODS 贴源、低成本、可追溯的定位不一致。因此本 PRD 将原“ODS 装载 + `_tmp` swap”方案改为：

```text
GCS Parquet
  -> ashare.ods_* external tables
  -> ashare.dwd_* native tables
```

不解决会导致 ODS 重复存储、装载流程复杂化，并让后续 DWD transform 多依赖一层不必要的 native copy。

## 3. 影响模块声明

| 模块 | 是否影响 | 说明 |
| --- | --- | --- |
| `data_layer` | 否 | 策略不直接读 ODS |
| `engine` / `account` / `strategy` / `analytics` / `utils` | 否 | 不修改 |

## 5. 需求详情

### 5.1 功能目标

- 不把 GCS Parquet 复制成 BigQuery native ODS 表。
- 用 BigQuery external table 挂载当前 GCS Parquet。
- ODS 表位于单 dataset `ashare` 下，表名前缀为 `ods_`。
- manifest/errors 控制表仍为 BigQuery native 表，用于审计和追踪，不承载业务数据副本。
- `audit-ods` 改为 external table 审计：表存在、schema 可读、GCS URI 匹配、sample query 可执行、对象数可对账。
- DWD transform 从 ODS external table 读取，并写入 DWD native table。

### 5.2 ODS external table 设计

每张业务表对应一张 external table：

```text
data-aquarium.ashare.ods_fact_equity_kline_1d
data-aquarium.ashare.ods_fact_fund_kline_1d
data-aquarium.ashare.ods_fact_index_kline_1d
data-aquarium.ashare.ods_fact_board_component_1d
data-aquarium.ashare.ods_dim_security
```

配置示例：

```yaml
ods_external_tables:
  fact_equity_kline_1d:
    destination_table: "ods_fact_equity_kline_1d"
    source_uris:
      - "gs://data-aquarium/a-share/standardized_parquet/fact_equity_kline_1d/**/*.parquet"
    source_format: "PARQUET"
    hive_partitioning:
      mode: "AUTO"
      source_uri_prefix: "gs://data-aquarium/a-share/standardized_parquet/fact_equity_kline_1d/"
    require_hive_partition_filter: false
```

如果实际 GCS 路径不支持 `**` glob，应由 manifest 中的对象列表按表生成 source URI 列表；不得改变 GCS 数据布局。

### 5.3 控制表

控制表仍使用 native BigQuery 表：

- `ashare.ods_external_manifest`
- `ashare.ods_external_errors`

manifest 记录 GCS 对象、目标表、对象大小、generation、source_file/source_entry、row_count（若可读取 Parquet metadata）。

errors 记录 external table 创建失败、schema 不兼容、sample query 失败、GCS 对象缺失、manifest 对账失败。

### 5.4 CLI 语义

| 命令 | 语义 |
| --- | --- |
| `init-ods` | 确认 `ashare` dataset，创建/确认 native 控制表 |
| `manifest` | 扫描 GCS prefix，生成本地 manifest |
| `create-ods-external` | 创建或更新 `ashare.ods_*` external table |
| `audit-ods` | 审计 external table 与 GCS 对账 |
| `sync-manifest` | 以 APPEND + batch_id 幂等方式同步 manifest |
| `load-ods` | 不再作为主命令；若保留 alias，必须报 deprecated 并引导到 `create-ods-external` |

### 5.5 交互流程

```text
现有 GCS Parquet
  -> manifest 扫描对象
  -> create-ods-external 创建 ashare.ods_* 外部表
  -> audit-ods 验证外部表可查、schema 可读、对象可对账
  -> PRD_12 transform-dwd 从 external ODS 读取并写 native DWD
```

## 6. 配置变更

| 配置项 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `dataset` | STRING | `ashare` | 单 dataset |
| `gcs.prefix` | STRING | `a-share/standardized_parquet` | 唯一 GCS 输入源 |
| `ods_external_tables.<table>.destination_table` | STRING | `ods_<table>` | external table 名 |
| `ods_external_tables.<table>.source_uris` | LIST | 按表配置 | GCS Parquet URI |
| `ods_external_tables.<table>.source_format` | STRING | `PARQUET` | 外部表格式 |
| `ods_external_tables.<table>.hive_partitioning` | MAP | 按表配置 | Hive 分区解析 |
| `defaults.ods.external_table_type` | STRING | `external` | 明确 ODS 不做 native copy |

删除或废弃：

- `defaults.use_tmp_table_swap`
- `defaults.replace_staging_tables`
- `defaults.load_strategy`
- ODS 业务数据表的 native load 配置

## 7. 不可改动的红线区域

- 不复制 GCS Parquet 到 BigQuery native ODS 表。
- 不创建 `_tmp` ODS 业务表。
- 不使用 `WRITE_TRUNCATE` / `WRITE_APPEND` 写 ODS 业务表。
- 不删除 `gs://data-aquarium/a-share/standardized_parquet/`。
- 不修改 GCS 对象布局。
- 不让策略或回测直接读取 ODS external table。
- DWD 必须是 native BigQuery table，不能也做 external table。

## 9. 验收标准

- `ashare.ods_*` P0 external table 全部存在。
- `bq show --format=prettyjson data-aquarium:ashare.ods_fact_equity_kline_1d` 显示存在 `externalDataConfiguration`。
- `externalDataConfiguration.sourceFormat == "PARQUET"`。
- `externalDataConfiguration.sourceUris` 全部指向 `gs://data-aquarium/a-share/standardized_parquet/` 下对象。
- BigQuery 中不存在由本 PRD 创建的 native ODS 业务数据副本。
- `ashare.ods_external_manifest` 同步成功，batch_id 幂等。
- `audit-ods` sample query 成功，且至少能读取 P0 表 1 行。
- GCS 对象数与 manifest 对账通过。
- DWD transform 可从 external ODS 发起 dry-run 或小样本 query。

### 测试用例输入输出

**用例 1：external table 配置**

- 输入：`target_table=fact_equity_kline_1d`
- 预期输出：BigQuery table id 为 `data-aquarium.ashare.ods_fact_equity_kline_1d`，且含 `externalDataConfiguration`

**用例 2：禁止 native ODS**

- 输入：执行 `create-ods-external`
- 预期：不产生 `_tmp_*` 表，不产生 native ODS 业务表 load job

**用例 3：GCS URI**

- 输入：任意 ODS external table 的 source URI
- 预期：以 `gs://data-aquarium/a-share/standardized_parquet/` 开头

### 回测验证要求

本 PRD 不跑回测。PRD_12 生成 native DWD 后再做回测可复现验收。

## 10. 备注

- ODS external table 会在查询时读取 GCS Parquet，性能通常弱于 native table；这是贴源层可接受的成本。
- DWD 是回测读取层，必须是 native table，用于稳定性能、去重和强类型。
- 如果未来 GCS 文件布局变化，必须先更新 manifest 和 external table 配置，再允许 DWD transform。
