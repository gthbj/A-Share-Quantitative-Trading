## 2. 背景与动机

当前框架仅支持日线级回测（`frequency="daily"`），策略信号每日收盘后生成、下一交易日开盘时成交。对于日内策略（如开盘跳空策略、盘中均线突破策略、高频统计套利等），日线级回测的粒度过于粗糙，无法捕捉分钟级别的价格波动与成交时机。

架构文档（`ARCHITECTURE.md` 第 4.5 节）已预留分钟级扩展接口：
- `BaseDataSource.get_daily_bars` 可扩展为 `get_bars(period="1min")`
- `BacktestEngine` 的逐日循环可改写为逐 Bar 循环

本次需求将正式实现分钟级回测，使框架具备 **日线 / 分钟线双频回测能力**。

**不实现的后果**：
- 日内策略无法在本框架中进行有效回测验证。
- 策略开发受限，仅能覆盖低频择时/选股场景，丧失中高频策略研发能力。

## 3. 影响模块声明

| 模块 | 影响程度 | 说明 |
|------|----------|------|
| `data_layer/` | **核心修改** | 数据源接口扩展分钟级获取；本地缓存需区分周期存储 |
| `engine/` | **核心修改** | `BacktestEngine` 主循环从逐日改为可配置的逐 Bar 循环；记录格式需支持分钟精度 |
| `config/` | 新增配置项 | `backtest.yaml` 增加 `frequency` 配置 |
| `account/` | 轻量适配 | T+1 规则在分钟级回测中仍以**交易日**为维度，minute-level 解冻逻辑需确认 |
| `analytics/` | 轻量适配 | 年化系数、回撤计算需根据频率自动调整（日线按 252，分钟线按 252×240） |
| `strategy/` | 无侵入 | 策略代码无需修改，`handle_data` 每个 Bar 仍被调用一次 |

**回测可复现性**：本次修改为确定性逻辑，不破坏可复现性。但分钟级数据量远大于日线，需关注内存与性能。

## 4. 关键文件路径与现有函数签名

### 4.1 `data_layer/base_data_source.py` — 数据源抽象基类

```python
# data_layer/base_data_source.py
class BaseDataSource(ABC):
    @abstractmethod
    def get_daily_bars(
        self,
        code: str,
        start_date: str,
        end_date: str,
        adjust: str = "qfq",
    ) -> pd.DataFrame:
        """获取日K线数据。"""
        raise NotImplementedError

    def get_multi_daily_bars(
        self,
        codes: List[str],
        start_date: str,
        end_date: str,
        adjust: str = "qfq",
    ) -> Dict[str, pd.DataFrame]:
        """批量获取多只股票日K线。"""
        result: Dict[str, pd.DataFrame] = {}
        for code in codes:
            df = self.get_daily_bars(code, start_date, end_date, adjust)
            if not df.empty:
                result[code] = df
        return result
```

## 5. 需求详情

### 5.1 功能目标

1. **统一数据接口**：将 `BaseDataSource.get_daily_bars` 重构为 `get_bars`，增加 `period` 参数，支持 `"daily"`、`"1min"`、`"5min"`、`"15min"`、`"30min"`、`"60min"`。
2. **数据源实现**：`AKShareDataSource` 实现分钟级数据拉取（AKShare 的 `stock_zh_a_hist` 支持 `period` 传入分钟周期），并落盘到本地缓存。
3. **本地缓存适配**：`LocalStorage` 的缓存文件名需包含周期信息，如 `000001_1min.parquet`，避免日线与分钟线数据互相覆盖。
4. **回测频率配置**：`BacktestEngine` 增加 `frequency` 参数（默认 `"daily"`），主循环根据频率自动切换为逐日或逐 Bar 推进。
5. **T+1 规则兼容**：分钟级回测中，T+1 仍以**交易日**为维度。当日任意时刻买入的股票，在当日剩余所有分钟内均不可卖；下一交易日开盘后（9:30）才可卖。
6. **绩效分析适配**：`analytics/metrics.py` 中年化系数需根据频率自动调整，避免分钟级回测使用日线的 252 天年化系数导致指标失真。
7. **CLI 入口扩展**：`run_backtest.py` 增加 `--frequency` 参数，支持命令行指定回测频率。

### 5.2 交互流程

#### 日线回测（现有逻辑，保持不变）

```text
for each trading_day:
    load daily_bar
    strategy.handle_data(context, daily_bar)
    execute_orders
    record daily_nav
```

#### 分钟级回测（新增逻辑）

```text
for each trading_day:
    load all minute_bars of this day (9:30~11:30, 13:00~15:00)
    for each minute_bar in chronological order:
        if first_bar_of_day:
            portfolio.before_trading(date)  # 解冻 T+1
            strategy.before_trading_start(context, current_minute_bar)
        strategy.handle_data(context, current_minute_bar)
        execute_orders
        record_nav  # 每个 Bar 结束记录一次
    strategy.after_trading_end(context, last_minute_bar)
```

**关键时序说明**：
- `before_trading_start` 仅在每个交易日的**第一个分钟 Bar**（9:30）调用一次，而非每个 Bar 调用。
- `after_trading_end` 仅在每个交易日的**最后一个分钟 Bar**（15:00）调用一次。
- T+1 解冻在每日开盘前（9:30 第一个 Bar 之前）执行，与日线回测一致。

## 7. 不可改动的红线区域

1. **策略接口不可变**：`BaseStrategy.handle_data(context, data)` 的签名与调用时机**不得修改**。参数 `data` 仍为 `Dict[str, pd.Series]`（单个 Bar 数据），策略层无感知频率切换。
2. **日线回测行为不可变**：当 `frequency="daily"` 时，回测流程、数据加载路径、NAV 记录格式必须与修改前**完全一致**，确保向后兼容。
3. **TradeEngine 撮合逻辑不可变**：分钟级 Bar 进入撮合引擎时，涨跌停判定、滑点、费用计算逻辑保持不变。
4. **Position T+1 语义不可变**：`sellable_qty` 的解冻逻辑仍以**交易日**为维度，不允许改为逐分钟解冻。
5. **回测可复现性不可破坏**：相同配置、相同策略、相同数据，多次运行结果必须完全一致。

## 9. 验收标准

### 9.1 功能验收

- [ ] `BaseDataSource.get_bars(code, start, end, period="1min")` 可返回分钟级 DataFrame，列包含 `[code, date, open, high, low, close, volume, amount]`。
- [ ] `AKShareDataSource` 拉取分钟级数据后，本地缓存文件名为 `{code}_{period}.parquet`（如 `000001_1min.parquet`），不与日线缓存冲突。
- [ ] `BacktestEngine` 在 `frequency="daily"` 时，回测结果（NAV 曲线、交易记录）与修改前完全一致。
- [ ] `BacktestEngine` 在 `frequency="1min"` 时，主循环按分钟 Bar 逐条推进，每个 Bar 调用一次 `strategy.handle_data()`。
- [ ] 分钟级回测中，T+1 规则正确：当日买入的股票在当日剩余分钟内不可卖，下一交易日 9:30 后才可卖。
- [ ] `run_backtest.py --frequency 1min` 可正常执行并输出报告。

### 9.2 测试用例

**用例 1：数据源分钟级获取**
- **输入**：`data_source.get_bars("000001.SZ", "20240101", "20240105", period="1min")`
- **预期输出**：DataFrame 行数 ≈ 4 个交易日 × 240 分钟 = 960 行（不含停牌），时间列包含分钟精度。

**用例 2：分钟级回测逐 Bar 推进**
- **输入**：`BacktestEngine(frequency="1min", start_date="20240101", end_date="20240105")`
- **预期行为**：
  - 策略 `handle_data` 被调用约 960 次（每个分钟 Bar 一次）。
  - `before_trading_start` 仅在 1 月 2 日、3 日、4 日、5 日每天 9:30 调用一次（共 4 次）。
  - `after_trading_end` 仅在每天 15:00 调用一次（共 4 次）。

**用例 3：T+1 在分钟级中的正确性**
- **输入**：某交易日 10:00 策略买入 `000001.SZ` 1000 股，当日 14:00 策略发出卖出信号。
- **预期行为**：
  - 10:00 买入成交，`sellable_qty = 0`。
  - 14:00 卖出订单进入撮合引擎，`TradeEngine` 检查 `sellable_qty <= 0`，**拒绝成交**。
  - 下一交易日 9:30 开盘后，`portfolio.before_trading()` 解冻，`sellable_qty = 1000`，此时可正常卖出。

### 9.3 回测验证

使用 `DoubleMAStrategy` 进行双频对比回测：
- **参数**：`--start 20240101 --end 20240331 --capital 1000000`
- **日线组**：`frequency=daily`，记录累计收益率、最大回撤、夏普比率、交易次数。
- **分钟组**：`frequency=1min`，使用相同策略参数。
- **预期**：
  - 分钟组的交易次数 **显著多于** 日线组（分钟级信号更密集）。
  - 分钟组的累计收益率与日线组 **方向一致**（不要求数值完全相同，因为成交价格精度不同）。
  - 分钟组最大回撤 **不高于** 日线组（分钟级更及时止损/止盈）。

## 10. 备注

1. **数据量与性能**：1 分钟线数据量约为日线的 240 倍（A 股每日 4 小时交易）。全 A 股 1 分钟回测对内存和 CPU 要求极高，建议初期仅对少量股票（universe < 10 只）或短区间（1~3 个月）进行分钟级回测。未来可通过逐日懒加载、多进程并行优化性能。
2. **AKShare 分钟数据限制**：AKShare 的 `stock_zh_a_hist` 分钟级接口可能有调用频率限制或历史数据长度限制（如仅提供最近 1 年的分钟数据），PRD 中默认使用 AKShare，若数据不足需在日志中提示用户。
3. **基准指数分钟数据**：`benchmark` 的分钟级加载逻辑与日K一致，通过 `get_bars(benchmark, period=frequency)` 获取。若 AKShare 不支持指数分钟数据，可降级为日线基准（允许不匹配）。
4. **Lookahead Bias 防范**：分钟级回测中，策略在 `t` 时刻只能使用 `t` 时刻及之前的 Bar 数据。`BacktestEngine` 的逐 Bar 循环天然满足此约束，无需额外防护。
5. **后续扩展**：未来可在此基础上扩展 `tick` 级别回测（逐笔成交），但不在本次需求范围内。
