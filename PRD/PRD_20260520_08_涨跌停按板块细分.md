# PRD_20260520_08：涨跌停规则按板块细分

> **关联 TODO**：TBD-4

## 一、背景

`engine/trade_engine.py:_try_fill` 中涨跌停判定写死 ±10%：

```python
up_limit = prev_close * 1.1
down_limit = prev_close * 0.9
# 简化：主板10%，实际需区分科创板20%、ST 5%
```

实际上 A 股不同板块涨跌幅有差异：

| 板块 | 涨跌幅 | 代表前缀 |
|------|--------|----------|
| 主板（沪/深） | ±10% | 60xxxx.SH、000/001/002/003xxxx.SZ |
| 创业板 | ±20%（2020-08-24 起，之前 ±10%） | 300/301xxxx.SZ |
| 科创板 | ±20% | 688/689xxxx.SH |
| ETF / LOF / 可转债 | ±10% | 51/56/58/11xxxx.SH、15/16xxxx.SZ |

写死 ±10% 会让创业板/科创板回测的成交假设过严（实际触及 ±15% 也算正常波动，但当前会被拦截）。

---

## 二、需求

1. 新增 `utils.code.price_limit_pct(code, current_date) -> float` 函数，按板块返回涨跌停比例
2. `TradeEngine._try_fill` 改用该函数，取代硬编码 ±10%
3. 创业板需按 `current_date` 切换：2020-08-24 起 ±20%，之前 ±10%
4. 补充单元测试覆盖所有分支
5. 同步更新 ARCHITECTURE.md（§2.3、§4.10、§6）和 TODO.md

---

## 三、设计

### 3.1 `price_limit_pct(code, current_date="")` 规则表

| 代码模式 | 板块 | 涨跌幅 |
|----------|------|--------|
| `60xxxx.SH` | 沪市主板 | 0.10 |
| `000/001/002/003xxxx.SZ` | 深市主板（含原中小板） | 0.10 |
| `688/689xxxx.SH` | 科创板 | 0.20 |
| `300/301xxxx.SZ` | 创业板 | 0.20（≥2020-08-24）/ 0.10（<2020-08-24） |
| `51/56/58/11xxxx.SH` | 沪 ETF/LOF/可转债 | 0.10 |
| `15/16xxxx.SZ` | 深 ETF/LOF | 0.10 |
| 其他 | fallback | 0.10 |

### 3.2 创业板日期判定

```python
_CHINEXT_REFORM_DATE = datetime.date(2020, 8, 24)
```

`current_date` 支持以下格式：
- `YYYYMMDD`（如 `20240515`）
- `YYYY-MM-DD`（如 `2024-05-15`）
- `YYYY/MM/DD`

无 `current_date` 时（如 `paper_trader` 调用未传入）默认采用最新规则 ±20%。

### 3.3 不在本期范围

以下规则**不实现**，作为新 TODO 入档：

- **ST/*ST 股票 ±5%**：当前数据源（5min K 线表）无 ST 标签
- **北交所 ±30%**：`utils/code.py` 当前不接受北交所代码（前缀 4/8 不在 `_SH_PREFIXES`/`_SZ_PREFIXES`），需先扩展代码归一化
- **新股上市首日**：需 `list_date` 字段，数据源未提供

## 五、风险与边界

- **北交所代码**：当前 `normalize_code` 不接受前缀 4/8，所以 `price_limit_pct` 即使写了北交所分支也不会触发。本期不扩展代码归一化，因为牵涉 `data_layer` 是否支持北交所数据，超出范围
- **跨境 ETF**：理论上跨境 ETF 涨跌幅可能不同，本期统一按 ±10% 处理。后续若需要细分，再加白名单
- **集合竞价/盘后定价**：±10% 仅指连续竞价时段，不影响本项目（项目按 bar 撮合，不涉及集合竞价细节）
