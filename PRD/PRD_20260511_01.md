## 2. 背景与动机

当前框架的 `AKShareDataSource` 统一使用 `ak.stock_zh_a_hist()` 接口获取行情数据，该接口主要覆盖 A 股个股。当用户尝试使用场内 ETF（如沪深300ETF `510300.SH`）作为策略标的或基准时，数据返回为空，导致回测无法运行。

**不实现的后果**：
- 用户无法使用 ETF 进行策略回测（如指数跟踪、ETF 轮动、股债平衡等常见策略）。
- 用户无法将 ETF 作为基准（benchmark）进行策略超额收益分析。
- 框架的资产覆盖范围局限于个股，无法满足大类资产配置类策略的需求。

        start_date: str,

        norm_code = self._normalize_code(code)
        ak_period = self._map_period(period)

        if self.use_cache:

                return cached

        # 2. 调用 AKShare 拉取
        df = pd.DataFrame()
        if period == "daily":
            try:
                df = ak.stock_zh_a_hist(
                    symbol=norm_code,
                    period=ak_period,

                    end_date=end_date,
                    adjust=adjust,
                )

                pass

            ...

## 5. 需求详情

### 5.1 功能目标

1. **资产类型自动识别**：根据代码特征自动判断标的类型（个股 / ETF / 指数），无需用户在配置中显式声明。
2. **ETF 数据接入**：对 ETF 标的调用 AKShare 的 `fund_etf_hist_em()` 接口获取日K与分钟K数据。
3. **指数数据接入**：对指数标的（如 `000300.SH`、`000001.SH`）调用 AKShare 的 `index_zh_a_hist()` 接口获取数据。
4. **统一输出格式**：无论标的类型如何，`get_bars()` 返回的 DataFrame 列名与格式必须与现有个股数据完全一致（`date`, `open`, `high`, `low`, `close`, `volume` 等），确保下游 `BacktestEngine` 与 `TradeEngine` 无需任何修改。
5. **本地缓存兼容**：ETF 与指数数据的缓存命名规则与个股保持一致（`{norm_code}.parquet`），不区分资产类型。

### 5.2 资产类型识别规则

| 资产类型 | 识别规则 | 示例 |
|---------|---------|------|
| **个股** | 不符合 ETF 或指数规则的，默认为个股 | `000001.SZ`, `600000.SH` |
| **ETF** | 代码前缀为 `15`, `16`, `51`, `56`, `58`, `59`（深交所/上交所 ETF 常见前缀） | `510300.SH`, `159919.SZ` |
| **指数** | 代码前缀为 `000`, `399`, `88` 且后缀为 `.SH` 或 `.SZ` | `000300.SH`, `399006.SZ` |

> **注意**：上述规则为启发式识别，覆盖 A 股市场 95% 以上常见标的。对于特殊代码（如新三板、B股、REITs），后续可通过配置项显式指定资产类型来扩展。

### 5.3 交互流程

```text
用户请求 get_bars("510300.SH", ...)
│
├─ 1. _normalize_code("510300.SH") → "510300"
├─ 2. 读取本地缓存（data/raw/daily/510300.parquet）
│       若命中 → 直接返回
│
└─ 3. 本地未命中 → 资产类型识别
        ├─ 前缀 51 → 判定为 ETF
        │   └─ 调用 ak.fund_etf_hist_em(symbol="510300", ...)
        ├─ 前缀 000 → 判定为指数
        │   └─ 调用 ak.index_zh_a_hist(symbol="000300", ...)
        └─ 其他 → 判定为个股
            └─ 调用 ak.stock_zh_a_hist(symbol="000001", ...)

        4. 数据写入本地缓存
        5. 返回统一格式 DataFrame
```

### 5.4 AKShare 接口映射

| 资产类型 | 日线接口 | 分钟线接口 | 备注 |
|---------|---------|-----------|------|
| 个股 | `ak.stock_zh_a_hist()` | `ak.stock_zh_a_hist()` | 现有逻辑 |
| ETF | `ak.fund_etf_hist_em()` | `ak.fund_etf_hist_em()` | 新增 |
| 指数 | `ak.index_zh_a_hist()` | `ak.index_zh_a_hist()` | 新增 |

**接口参数对照**：

```python

# ETF（新增）
ak.fund_etf_hist_em(symbol=norm_code, period=period, start_date=..., end_date=..., adjust=...)

# 指数（新增）
# 注意：index_zh_a_hist 的参数名可能不同，需现场确认
# 常见形式：ak.index_zh_a_hist(symbol="000300", period="daily")
```

> **风险点**：`index_zh_a_hist` 的参数签名与 `stock_zh_a_hist` 可能不完全一致（如不支持 `adjust` 参数，或参数名差异）。实现时需在调用前通过 `inspect` 或实际测试确认参数兼容性，必要时做参数过滤或转换。

## 7. 不可改动的红线区域

1. **`BaseDataSource` 抽象接口不可变**：`get_bars()` 的签名（参数名、类型、返回值类型）不得变更。
2. **`LocalStorage` 缓存格式不可变**：Parquet/CSV 的列结构、文件命名规则、目录组织方式保持原样。
3. **`BacktestEngine` 与 `TradeEngine` 不可变**：引擎层不感知标的类型，只消费 `get_bars()` 返回的标准化 DataFrame。
4. **个股数据获取逻辑不可破坏**：现有 `stock_zh_a_hist()` 的调用路径保持完整，修改不得影响已有回测结果。

## 10. 备注

1. **AKShare 接口稳定性**：`fund_etf_hist_em` 与 `index_zh_a_hist` 为 AKShare 的东财接口，与 `stock_zh_a_hist` 共享相同的数据源。若东财 API 在特定网络环境下不可用，三类资产的数据获取会同时受影响，这是 AKShare 免费接口的固有限制，不在本次需求解决范围内。
2. **指数的前复权**：部分指数接口可能不支持 `adjust` 参数（指数本身无除权除息，无需复权）。实现时若遇到参数不支持的情况，应静默忽略 `adjust` 参数，而非抛出异常。
3. **后续扩展**：未来可考虑接入 `fund_lof_hist_em`（LOF 基金）、`bond_zh_hs_daily`（债券）等接口，进一步扩展资产覆盖范围。
4. **网络问题说明**：当前运行环境中，AKShare 的东财接口（`push2his.eastmoney.com`）无法访问（服务器返回 Empty reply）。此问题需在实施本需求前先行解决，或采用本地 CSV/Parquet 导入方式绕过网络限制进行代码逻辑验证。
