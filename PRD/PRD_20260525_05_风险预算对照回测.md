## 2. 问题描述

上一轮 ML 多周期策略回测显示，策略在 2020 年反弹期因风险预算过低而显著跑输沪深300。用户要求只跑两组对照实验：

1. 新手续费 + 新风险预算。
2. 新手续费 + 新风险预算 + `crisis` 清仓层。

当前策略只有 `bull / neutral / bear` 三态，且 `bear` 默认不买入并可清仓；若要验证“bear 只是降风险、crisis 才清仓”，需要给策略增加可配置的 `crisis` 状态，并提供两个独立 preset 方便 Cloud Run 对照回测。

最小复现路径：

1. 运行 `python run_backtest.py --preset ml_multi_horizon_picker_bear_budget --start 20200102 --end 20260430 --capital 100000 --daily-diagnostics`。
2. 运行 `python run_backtest.py --preset ml_multi_horizon_picker_crisis_budget --start 20200102 --end 20260430 --capital 100000 --daily-diagnostics`。
3. 对比两组最终收益、最大回撤、相对沪深300超额、平均仓位与空仓天数。

## 5. 需求详情

### 功能目标

1. 增加可选 `crisis` regime，用于真正的清仓/零预算场景。
2. `bear` 支持非零目标持仓与非零资金预算；若 `target_n > 0` 且 `position_pct > 0`，允许按模型分数补仓。
3. 保持默认 `ml_multi_horizon_picker` 行为不变，避免影响现有 preset。
4. 新增两个实验 preset：
   - `ml_multi_horizon_picker_bear_budget`
   - `ml_multi_horizon_picker_crisis_budget`
5. 两组都使用新手续费“万一免五”，完整跑 `20200102~20260430`。

### 交互流程

用户指定实验 preset → Cloud Run 构建镜像 → 分别执行两组回测 → 输出每日诊断 CSV 和报告到 GCS → 汇总两组最终收益、最大回撤、沪深300对比、持仓暴露与空仓情况。

## 6. 配置变更

新增两个 preset：

| preset | bull | neutral | bear | crisis | 说明 |
|---|---:|---:|---:|---:|---|
| `ml_multi_horizon_picker_bear_budget` | 5只 / 85% | 4只 / 60% | 2只 / 30% | 不启用 | bear 只降风险，不清仓。 |
| `ml_multi_horizon_picker_crisis_budget` | 5只 / 85% | 4只 / 60% | 2只 / 30% | 0只 / 0% | severe stress 时进入 crisis 并清仓。 |

## 9. 验收标准

用例 1：bear 非零预算

- 输入：`regime=bear`、`target_n=2`、`position_pct=0.30`、`bear_clear_existing=false`
- 修改前行为：bear 不开新仓。
- 修改后预期：允许在满足模型阈值时补仓到目标风险预算。

用例 2：crisis 清仓

- 输入：指数 5 日快速下跌超过阈值或 20 日回撤超过阈值。
- 修改后预期：若 `crisis_enabled=true`，regime 返回 `crisis`，目标持仓数为 0，资金预算为 0%，可卖持仓被清掉。

回测验证要求：

- 第 2 组：`--preset ml_multi_horizon_picker_bear_budget --start 20200102 --end 20260430 --capital 100000 --daily-diagnostics`
- 第 3 组：`--preset ml_multi_horizon_picker_crisis_budget --start 20200102 --end 20260430 --capital 100000 --daily-diagnostics`
- 预期输出：两组 GCS 归档结果、最终收益、最大回撤、沪深300收益、相对沪深300超额、平均现金比例、空仓天数。
