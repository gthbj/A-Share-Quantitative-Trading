# 2. 背景与动机

当前 `ml_multi_horizon_picker` 的市场状态判定只依赖沪深300是否跌破 MA200。该规则过于滞后，在 2020 年 2 月和 3 月的快速下跌中，策略仍多次处于 `bull` 并维持较高持仓。即便进入 `bear`，当前行为也只是“不新开仓 + 止损收紧”，并不会把已有仓位降到风险预算内，导致 10 万资金、少数标的集中持仓时回撤被放大。

本需求将 `bull / neutral / bear` 从简单趋势标签升级为可执行的风险预算约束：

- `bull`：最多 5 只，允许较高仓位。
- `neutral`：最多 3 只，显著降低资金使用比例。
- `bear`：目标持仓 0，只保留 T+1 当日不可卖的仓位，后续可卖即清。

不实现的后果是：策略在快速下跌或市场广度恶化时仍可能满仓或高仓位持有少数高波动股票，止损滞后时单票损失会远大于配置阈值。

# 5. 需求详情

## 功能目标

1. 将 regime 判定从单一 MA200 改为多信号风险评分：
   - 指数趋势：MA60 / MA120 / MA200、MA60 斜率。
   - 动量：近 20 / 60 日收益。
   - 回撤：近 20 / 60 日最大回撤、近 5 日急跌。
   - 波动：20 日波动率相对历史分位和 60 日波动率。
2. 引入市场广度修正：
   - 如果股票池中在 MA20 上方的比例过低、近 20 日正收益比例过低、近 5 日急跌比例过高，则把状态降为 `bear`。
   - 市场广度恢复只能把 `bear` 先修正到 `neutral`，不直接跳到 `bull`。
3. 将 3~5 只持仓策略改成 regime 预算：
   - `bull`: `target_n=5`, `position_pct=0.85`
   - `neutral`: `target_n=3`, `position_pct=0.45`
   - `bear`: `target_n=0`, `position_pct=0.0`
4. `bear` 必须成为强约束：
   - 可卖持仓全部下卖单，理由标记为 `bear_risk_budget_clear`。
   - 不允许新开仓。
   - T+1 不可卖持仓不会被强制违反交易规则，下一交易日可卖后再清。
5. 当当前持仓数量或市值超过当前 regime 预算时，优先卖出评分最低的可卖持仓，且当天不再补仓，避免卖出后立刻买回。

## 交互流程

```text
每日收盘信号日 T
→ 加载当日可见行情和模型
→ 对股票池打分
→ 用沪深300历史 + 股票池广度计算 regime
→ 根据 regime 得到目标持仓数和资金预算
→ 先执行止损/排名/卖出模型等卖出触发
→ 再执行风险预算降仓
→ 若 regime=bear 或触发预算降仓，当天不再新买
→ 若仍有预算和空位，按 Top 候选补仓
→ 订单在 T+1 开盘按现有撮合规则执行
```

# 9. 验收标准

1. 用例 1：快速下跌但未跌破 MA200
   - 输入：指数长期上行后短期 20 日回撤超过阈值，且近 5 日跌幅较大。
   - 修改前行为：仍可能是 `bull` 或 `neutral`。
   - 修改后预期：返回 `bear` 或至少不返回 `bull`。
2. 用例 2：市场广度恶化
   - 输入：指数基础状态为 `bull`，但股票池中 `close_to_ma20 > 0` 比例低于 `35%`。
   - 修改后预期：组合状态降为 `bear`。
3. 用例 3：bear 清仓
   - 输入：当前有 3 只可卖持仓，regime=`bear`。
   - 修改后预期：对 3 只可卖持仓生成卖出订单，不生成买入订单。
4. 用例 4：neutral 风险预算
   - 输入：当前有 4 只持仓，neutral 预算最多 3 只且资金预算 45%。
   - 修改后预期：卖出评分最低或导致超预算的持仓，当天不再补仓。
5. 回测验证要求：
   - 参数：`ml_multi_horizon_picker`，`20200102~20200612`，初始资金 `100000`。
   - 预期方向：最大回撤应低于旧版本已观测的 `-36.89%`；交易次数可能增加；空仓天数应增加。

# 10. 备注

- 本需求不承诺收益率提升，只优先降低极端回撤。
- 多信号 regime 不是预测牛熊市，而是风险预算开关。
- 市场广度来自当日股票池特征，不引入额外数据表；但股票池本身只覆盖流动性 Top-N，不能代表全市场所有股票。
- bear 清仓受 T+1 和开盘跳空约束，实际成交损失仍可能超过阈值。
