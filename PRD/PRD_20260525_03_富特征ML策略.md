### 5.2 数据加载方案

**核心：3 表 BQ JOIN 在 SQL 层完成**，Python 端只接收宽表。

```sql
WITH daily AS (
  SELECT equity_code, date, close, high, ma_60, amount,
         return_1d, return_5d, ...
  FROM dws_equity_daily_features
  WHERE date BETWEEN ... AND adjust_type = @adjust
    AND equity_code IN UNNEST(@codes)
),
fundamental AS (
  SELECT equity_code, date,
         pe_basic, pb, roe, gross_margin, net_margin,
         debt_to_assets, market_cap, asset_turnover
  FROM dws_equity_fundamental_features
  WHERE date BETWEEN ... AND equity_code IN UNNEST(@codes)
),
event AS (
  SELECT equity_code, date,
         net_inflow_amount, main_net_inflow_amount,
         dragon_tiger_net_amount, limit_up_streak, is_kpl_event
  FROM dws_equity_event_money_flow_features_1d
  WHERE date BETWEEN ... AND equity_code IN UNNEST(@codes)
)
SELECT d.*,
       f.pe_basic, f.pb, f.roe, f.gross_margin, f.net_margin,
       f.debt_to_assets, LN(f.market_cap + 1) AS log_market_cap,
       f.asset_turnover,
       SAFE_DIVIDE(e.net_inflow_amount, d.amount) AS net_inflow_pct,
       SAFE_DIVIDE(e.main_net_inflow_amount, d.amount) AS main_net_inflow_pct,
       SAFE_DIVIDE(e.dragon_tiger_net_amount, d.amount) AS dragon_tiger_net_pct,
       e.limit_up_streak,
       CAST(IFNULL(e.is_kpl_event, FALSE) AS INT64) AS is_kpl_event_int
FROM daily d
LEFT JOIN fundamental f ON d.equity_code = f.equity_code AND d.date = f.date
LEFT JOIN event e ON d.equity_code = e.equity_code AND d.date = e.date
```

LEFT JOIN：基本面 / 事件特征缺失时记为 NULL，模型训练时 NaN handling 由 LightGBM 自己处理（LightGBM 原生支持 NaN）。

### 5.3 关键设计决策

#### A. 为什么 LEFT JOIN（不是 INNER）

某些股票某些日期没有龙虎榜事件、新股没有完整 1 年基本面历史——INNER JOIN 会丢样本。
LightGBM 对 NaN 天然支持，作为"特征缺失"的额外信号往往有用。

#### B. 为什么把基本面直接用做特征而不归一化

LightGBM 是 tree-based 模型，对单调变换不敏感（PE=10 和 PE=20 的相对顺序就够了）。
不需要 z-score，节省一步。

但 `market_cap` 范围跨 5-6 个数量级（亿到万亿），用 `LN(x+1)` 压一下让分裂更均匀。

#### C. 缺失值处理

- LightGBM 训练时：直接喂 NaN，库自己决定分裂方向
- 推理时：feature_df 中可能某只股票某天缺基本面 → 用 NULL，LightGBM 输出仍正常
- **不做**：均值填充、前向填充——会引入 lookahead 风险

#### D. Adjust Type

`dws_equity_fundamental_features` 没有 `adjust_type`（基本面与复权无关），只有
daily_features 表有 `adjust_type`。统一用 `qfq` 拉 daily，与 fundamental / event JOIN 时
按 `(equity_code, date)`。

#### E. Universe 选择

复用 v1：从 daily volume 算 top N by liquidity（默认 500），trading_permissions 过滤
科创/创业/北交/ST/退市。

## 10. 备注

### 10.1 Lookahead Bias 防护

| 风险点 | 防护 |
|---|---|
| Fundamental 用财报数据 | `dws_equity_fundamental_features` 已用 `announcement_date` 派生 partition（PRD_06 §10.1 红线）|
| Money flow 用龙虎榜事件 | 龙虎榜是 T 日盘后发布，T+1 才知道——但本策略 T 日 close 计算特征 T+1 开盘下单，已避开 |

### 10.3 预期性能提升（凭经验）

参考量化文献：

- 单纯技术面 IC ≈ 0.02-0.04
- 技术 + 基本面 IC ≈ 0.04-0.06（+50-100%）
- 加事件资金流后 IC ≈ 0.05-0.07

- Multi-task learning（同一模型同时输出 buy/sell prob）
