## 2. 背景与动机

当前框架完全依赖 AKShare 的东财接口（`push2his.eastmoney.com`）获取行情数据。在实际运行中，该接口频繁出现以下问题：
- **IP 封禁**：频繁请求后触发反爬机制，返回 `Empty reply from server`。
- **网络限制**：特定网络环境（如公司/学校防火墙）屏蔽了东财 API 域名。
- **接口不稳定**：东财 API 偶尔维护或调整参数，导致批量拉取失败。

当 AKShare 不可用时，框架完全停摆，用户无法运行任何回测。引入多数据源 Fallback 机制后，当主数据源（AKShare）失败时，自动切换至备用数据源（Tushare Pro），确保回测可用性。

**不实现的后果**：
- 用户在网络受限或 IP 被封时完全无法使用框架。
- 每次遇到网络问题都需要手动切换网络或等待解封，体验极差。

## 5. 需求详情

### 5.1 功能目标

1. **新增 Tushare Pro 数据源**：实现 `TushareDataSource` 类，支持个股/ETF/指数的日K与分钟K获取，接口与 `AKShareDataSource` 完全对齐。
2. **配置化切换**：通过 `config/backtest.yaml` 的 `data.source` 字段选择数据源（`akshare` / `tushare`）。
3. **Token 管理**：Tushare Pro 需要注册获取 Token，通过配置文件传入，不在代码中硬编码。
4. **列名标准化**：无论底层是 AKShare 还是 Tushare，返回的 DataFrame 列名必须统一（`date`, `open`, `high`, `low`, `close`, `volume`, `amount`）。
5. **缓存兼容**：Tushare 数据源复用现有的 `LocalStorage` 缓存机制，缓存文件格式与 AKShare 完全一致。
6. **代码复用**：Tushare 与 AKShare 的列名标准化、日期格式处理、缓存读写逻辑应复用同一套 `_standardize_df()` 等工具方法，避免代码冗余。

### 5.2 Tushare 接口映射

| 资产类型 | Tushare 接口 | 说明 |
|---------|-------------|------|
| 个股/ETF 日K | `ts.pro_bar(ts_code='510300.SH', asset='FD', freq='D')` | ETF 需指定 `asset='FD'` |
| 个股/ETF 分钟K | `ts.pro_bar(ts_code='510300.SH', asset='FD', freq='1min')` | 需 Tushare 2000积分以上权限 |
| 指数日K | `ts.pro_bar(ts_code='000300.SH', asset='I', freq='D')` | 指数指定 `asset='I'` |

> **注意**：Tushare 的 `ts_code` 格式为 `代码.交易所`（如 `510300.SH`、`000001.SZ`），与框架的 `code` 格式一致，无需转换。

### 5.3 交互流程

```text
用户配置 data.source = "tushare"
│
└─ run_backtest.py
    └─ 根据配置初始化 TushareDataSource(token=cfg.data.tushare_token)
        └─ get_bars("510300.SH", "20220101", "20231231")
            ├─ 1. 读取本地缓存（复用 LocalStorage）
            ├─ 2. 缓存未命中 → 调用 ts.pro_bar()
            ├─ 3. 列名标准化（Tushare 返回的列名映射为统一格式）
            ├─ 4. 写入本地缓存
            └─ 5. 返回 DataFrame
```

```yaml

  tushare_token: ""        # Tushare Pro Token（如使用 Tushare）
  cache_dir: "data/raw"
  storage_format: "parquet"
```

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `data.source` | str | `akshare` | 数据源选择：`akshare` 或 `tushare` |

## 7. 不可改动的红线区域

1. **`BaseDataSource` 抽象接口不可变**：`get_bars()` 的签名与返回值格式不得变更。
2. **`LocalStorage` 缓存格式不可变**：Parquet/CSV 的列结构、文件命名规则、目录组织方式保持原样。
3. **现有 AKShare 逻辑不可破坏**：`AKShareDataSource` 的所有方法保持完整，Tushare 作为新增类独立存在。
4. **策略层与引擎层无感知**：`run_backtest.py` 通过配置切换数据源实例，策略和引擎不感知具体数据源实现。

- **AKShare 模式**：`data.source = "akshare"`，网络正常时回测成功。
- **Tushare 模式**：`data.source = "tushare"`，配置有效 Token 后回测成功，结果与 AKShare 模式接近（数据来源不同，微小差异属正常）。

## 10. 备注

1. **Tushare 积分要求**：`pro_bar` 接口的分钟级数据需要 2000 积分以上权限。日线数据通常免费或低积分即可。如果用户没有足够积分，分钟级回测在 Tushare 模式下会 fallback 到空数据。
2. **数据差异说明**：AKShare 和 Tushare 的数据源不同（东财 vs 财经数据服务商），同一股票的同一日收盘价可能存在微小差异（通常 < 0.1%）。这属于正常的数据源差异，不影响框架逻辑验证。
3. **Token 获取方式**：用户需在 [Tushare Pro 官网](https://tushare.pro) 注册账号，在个人中心获取 Token。
4. **与缓存增量更新（PRD_20260512_01）的关系**：两者独立。本 PRD 解决"数据源不可用"问题，PRD_20260512_01 解决"缓存数据不完整"问题。Tushare 数据源同样受益于缓存增量更新机制。
